# udemy-video-course

動画講座のレクチャーを、スライドとナレーション台本から**AI音声付きの動画**にするハーネス。
座学（スライド中心）と実践（ハンズオン）の両方を扱う。

実践レクチャーでは、制作者が画面録画ソフトで撮る代わりに、**Claude 自身がブラウザを操作して
1状態ずつ静止画を撮り、塗りつぶし・強調を入れてから動画に組む**モードを持つ。

## 全体像

```
[座学]   台本 + pptx ──────────────────────────► make-lecture-movie ──► mp4
[実践]   録画 or 画面操作 ──► record-practice-screen ──► make-practice-movie ──► mp4
                                    │                         │
                         cue_stills（強調を目視）              │
                                    ┌─────────────────────────┘
                                    ▼
                    qa_check / leakcheck ──► transcript-reviewer ──► 差し替え
```

実践の素材づくりには4つのモードがある。クラウドIDEでのコマンド実行、
ドキュメントの読み解き、Web管理コンソールのツアー、そして
**CLI で作って画面は「結果を読む」ために撮る**回。
管理画面のウィザードをクリックで通すのは失敗しやすいので、
**作る・壊すは CLI、画面は出来上がりを読むためだけに使う**と通りやすい。

静止画から組む回では、**尺を「合成済み音声の実尺 + 2.0秒」で決める**。
文字数の見積もりをそのまま完成尺にすると、余裕分がそのまま無音になる
（実測：見積もりだと沈黙率が2割超、実尺だと約10%）。

## スキル

| スキル | 役割 |
|---|---|
| `make-lecture-movie` | 台本＋pptx → AI音声付き動画。実践は既定でスキップする |
| `make-practice-movie` | 録画＋スライド → 録画に同期した実践動画。区間の粒度・沈黙率・映り込みの作法を含む |
| `record-practice-screen` | Claude が画面を操作して実践の素材（`_rec.mp4`）を撮る。塗りつぶしと強調まで |

## 参照ファイル

| ファイル | 役割 |
|---|---|
| `references/tts-readings.md` | **読み上げ表記一覧**。TTS が誤読する表記（例：`az` を「アズ」と読む）の、台本での書き方。台本を書く前に見る。誤読を見つけたら追記する |

## エージェント

| エージェント | 役割 |
|---|---|
| `transcript-reviewer` | 台本を画面・一次ドキュメントと突き合わせる第三者レビュー。重大度つきの指摘表を出す |

## スクリプト

| スクリプト | 何をするか |
|---|---|
| `lecture_movie.py` | 座学の音声合成・スライドPNG化・動画合成 |
| `practice_movie.py` | 実践の `calibrate` / `analyze` / `transcript-check` / `build` |
| `record` 系 | |
| `build_rec.py` | 静止画フレーム → `_rec.mp4` ＋台本の骨組み。**`--audio-dir` で音声の実尺から尺を決める** |
| `redact.py` | フレームの塗りつぶし（黒ベタ）と強調（周囲を暗くして枠）。`--probe` で座標を先に確認 |
| `box_fit.py` | 強調枠を**文字から 3px 以上離して**置き直し、すき間を検査する。空きが無ければ枠線を 4→3→2px に細くする。誤認する区間は `box_manual.json` で手置き |
| `render_frames.py` | `recipe.json` の塗り・強調を `raw/` に当てて `frames/` を描く（区間ごとの枠線の太さに対応） |
| `cue_stills.py` | 強調を当てた絵をコンタクトシート（4枚/枚）にまとめる。**組み立て前の目視検収**用 |
| `stage_diagram.py` | 段階的に積み上がる構成図を draw.io で生成。**外接矩形を固定**して図の伸縮を防ぐ |
| `QA` 系 | |
| `qa_check.py` | TTS異常（ループ・途切れ・**途中の長い無音**）・沈黙率・体言止め・管理番号を**1コマンド**で検査。静止画から組む回は `--audio-only` の直後にも走らせる |
| `verify_tts.py` | 合成した wav を STT で文字に戻し、**台本と同じ内容か**を照合する（別の文を読む・前置きが付く・冒頭が抜ける合成事故の検出）。Azure Speech（キーレス）を使う |
| `leakcheck.py` | 彩度ベースで映り込みの疑いがある区間を洗い出す（探索） |
| `find_text_leak.py` | 消したい文字列のテンプレートを全編に照合する（特定） |
| `detect_events.py` | 録画から画面が変化した瞬間を秒単位で列挙し、区間境界の候補にする（**実録画のみ**） |
| `shift_lead.py` | ナレーションが画面変化に先行するよう、区間の開始を前倒しする（**実録画のみ**） |

## 品質ゲート

**組み立てる前に1つ、`build` のあとに3つ。**

0. `cue_stills.py --sheets` — **強調を当てた絵を全数、目で見る**（静止画から組む回）
1. `qa_check.py <台本>` — 合成音声のループ・途切れ、沈黙率（10〜20%）、体言止め、管理番号
2. `leakcheck.py <動画>` — 映り込みの疑いがある区間（ヒットは必ず目視）
3. `transcript-reviewer` — 画面と台本の突き合わせ、一次ドキュメントでの事実確認

**0 を後回しにしない。** 強調の座標の誤りは数値を読んでも分からない。
実測では4レクチャーで9件見つかり、**座標のレビューで気づけたものは0件**だった。
組んだあとに直すと音声の合成からやり直しになる。

**3 を省かない。** 機械チェックはタイムコードと文字面しか見ないため、
「画面に映っていないものを語っている」「仕様として誤っている」は1件も拾えない。

**どのゲートも抜き取りでは当たらない。** 欠陥は1本あたり1〜6件で30〜50枚に散らばる。
枚数が多くてコストが気になるときは、1枚ずつ読むのをやめて
**コンタクトシート（4枚/枚）で全数見る**（画像のコストが約1/4になる）。

## 依存

```bash
pip install -r scripts/requirements.txt
```

加えて、システム側に **ffmpeg / ffprobe**、**LibreOffice（soffice）** が要る。
段階図を作るなら **draw.io desktop**、音声合成にはクラウドTTSの認証が要る。

## 講座固有のもの

用語規約・カリキュラム設計書・一次情報のスナップショットは**講座リポジトリ側に置く**。
このプラグインは作り方（ハーネス）だけを持つ。
