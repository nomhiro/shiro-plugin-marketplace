# record-practice-screen

実践（ハンズオン）レクチャーの**素材づくり**を担当するスキル。出力は
`lectures/<section>/<basename>_rec.mp4` で、そこから先は [[make-practice-movie]] が引き取る。

制作者が画面録画ソフトで撮る従来のやり方（モードA）に対して、本スキルは
**Claude がブラウザを操作し、状態ごとにスクリーンショットを撮って動画に組む**（モードB）。

## モードBを選ぶ理由

| | モードA（制作者のPC録画） | モードB（Claude が撮る） |
|---|---|---|
| 映り込み | 通知・タブ名・タスクバー・ブックマークが不意に入る | ページ内容だけ。**ブラウザのURLバーも入らない** |
| やり直し | 撮り直しは全部撮り直し | 1枚だけ撮り直せる |
| 同期 | 操作の瞬間に境界を合わせる作業が要る | **尺をナレーションから逆算**するのでズレない |
| 環境 | 制作者のPCに依存する | 誰の環境でも同じ画面になる |
| 待ち時間 | 実時間が動画に入る | 入らない（必要なら意図的に足す） |

一方、モードAにしかない良さもある：試行錯誤やエラーがそのまま教材になる。
**エラーの切り分けを見せたい回はモードA**、手順と画面の対応を見せたい回はモードB。

## 3つの収録モード（いずれも実証済み）

### B-1 クラウドIDE でコマンドを実行する回

エディタに該当のコードを開いたまま、**下のターミナルで1コマンドずつ実行する**固定レイアウト。
読んでいる行と実行結果が同じフレームに入るので「コードの読み解き」と噛み合う。

- 行送りはスクロールではなく**行番号ジャンプ**（スクロールは効かないことがある）
- ターミナルは**アカウント名がプロンプトに出ないシェル**を選ぶ
- レッスンのフォルダは事前にクリーンにする（前回の仮想環境や設定ファイルの残骸を消す）

### B-2 クラウドIDE でドキュメントを読み解く回

コマンドを実行しない回（設計・ワークシート・仕様の読み合わせ）。
**ターミナルパネルは閉じる**。空のターミナルが画面の1/3を占めても意味がない。

- Markdown は**プレビュー**で見せる。生のテキストだと表が読めない
- プレビューのフォントは既定のままだと動画で読めない。**20px 程度まで上げる**
- 準備のためにターミナルを使ったら、**撮る前にパネルごと閉じる**

### B-3 Web 管理コンソールをツアーする回

管理画面は**個人情報が出やすい**。塗りつぶしを前提に組み立てる（後述）。

- 画面遷移のあと **10〜15秒待つ**。管理コンソールは描画が遅い
- 右側のパネルが切れるときは**左ナビを折りたたむ**と収まる
- 1画面の情報量が多いので、**同じスクリーンショットに別の強調枠を描いて複数区間にする**

## 🔴 収録前に決めること

1. **何も作らない・何も消さない。** 課金リソースの作成、削除、送信ボタンは押さない。
2. **サインインは代行しない。** 資格情報の入力が要る画面に来たら止めて、制作者に頼む。
3. **表示言語を決める。** 受講者の環境に寄せるか、資料の表記に寄せるか。画面と資料が
   食い違うと必ず指摘される。日本語UIで撮るなら、資料とナレーションで英語名を併記する。
4. **塗る対象を先に列挙する。** 撮ってから考えると漏れる。

## 🔴 塗りつぶし（公開前の必須工程）

**ぼかしは使わない。** 条件次第で復元されうるし、「隠したつもり」が残る。
`redact.py` で**黒ベタ**にする。不可逆で、視聴者にも「伏せてある」と伝わる。

典型的な対象：

| 対象 | よく出る場所 |
|---|---|
| 氏名・表示名 | ダッシュボードの挨拶、アカウントメニュー |
| メールアドレス | 作成者・更新者の列、メンバー一覧 |
| テナント/サブスクリプション/リソースの ID | 詳細パネル、URL を含むフィールド |
| **他プロジェクト・他リソースの名前** | 横断の一覧、切替ドロップダウン |
| コストの実額 | 概況ダッシュボード |

補足：

- **切替ドロップダウンは開かない。** 他の作業物の名前が一覧で出る。
  スコープを変えたいときは**URL を直接組み立てて遷移**する。
- ブラウザ拡張が PII を自動でぼかすことがあるが、**それに頼らない**。必ず上から黒ベタで潰す。
- 座標は `redact.py --probe` で**先に拡大して確かめる**。当てずっぽうで塗ると端から文字がはみ出す。
- 塗ったあと、**全フレームを目視する**。1枚ずつ見る以外に確かめる方法はない。
- 教材として必要な値（受講者が次のレッスンで実際に使うエンドポイントなど）は**塗らない**。
  「リソース名を塗る」は他人の作業物を指す。

## ブラウザ操作の実測ルール

ここは何度も踏み直した落とし穴なので、そのまま従うこと。

1. **座標クリックは当てにしない。** ビューポートが呼び出しごとに変わる（実測で
   1374x730 / 1425x712 / 1512x803 / 1568x783 が混在した）。**要素を名前で探して
   ref を取ってからクリックする**。1つ前のスクリーンショットの座標は、もう合っていない。
2. **スクリーンショットの保存では縮小指定を付けない。** 縮小指定は**保存ファイルにも効く**。
   確認用に小さく見るのと、素材として保存するのは別の呼び出しにする。
3. **ターミナルは1文字目が落ちる。** コマンドの先頭に半角スペースを1つ入れる。
4. **打ち直しは Esc ではなく Ctrl+C。** Esc では入力行が消えず、途中に挿入される。
5. **ツールバーのボタンを押した直後はツールチップが残る。** 別の場所にポインタを移して
   3秒待ってから撮る。
6. **通知・コーチマークは本文ではなく閉じるボタンを押す。** 本文を押すと別の画面に飛ぶ。
7. **ダイアログを出さない。** モーダルが出ると以後の操作を受け付けなくなる。
8. 長い待ちは分割する。1回の待機に上限があるので、10秒×N回に分ける。

## フレームの組み立て

`build_rec.py` に任せる。要点は2つ。

- **尺はナレーションから逆算する。** `尺 = 文字数 / cps × 1.15 + 余白`。
  先にフレームの秒数を決めるとナレーションが必ずはみ出し、タイムコードの調整が延々と続く。
  余白は、画面を読ませる回（管理コンソールのツアーなど）では **2.5〜3.5秒**にする。
  喋りっぱなしだと視聴者の目が追いつかない。沈黙率は **10〜20%** が目安。
- **スクリーンショットは拡大縮小しない。** ビューポートが揺れるので、スケールし直すと
  区間ごとに文字の大きさが変わって見える。**キャンバスへパディングするだけ**にする。
  キャンバスより大きい図版だけ、収まるように縮める。

図解の回は `stage_diagram.py` で段階図を作る。**全段に不可視の白枠を入れて
外接矩形を固定する**のを忘れないこと（入れないと段ごとに図が伸縮する）。

## ⚠️ 既存の録画を上書きしない

`<basename>_rec.mp4` は、制作者が撮った元録画と同じ名前である。多くの構成で
この拡張子は git 管理外なので、**上書きすると復元できない**。
`build_rec.py` は既存ファイルを `.previous.mp4` に退避してから書き出す。

## 次の工程

フレーム → **塗り・強調（`redact.py`）** → `build_rec.py` → `analyze --force`
→ `transcript-check` → `build` → **`qa_check.py` と `leakcheck.py`**
→ [[transcript-reviewer]] によるレビュー → 差し替え
