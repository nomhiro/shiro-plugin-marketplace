# 制作チェックリスト（1枚）— 担当は最初にこれを読む

> Hyperframes のスライド型（`slide-format.md`）で1ユニットを作るときの関門。既存の規則を集めただけで、新しい規則は無い。
> 矛盾したら根拠の参照先が勝つ（正本: `unit-playbook.md`・`slide-format.md`・`quality-standards.md`・`quiz-authoring.md`・`tts-readings.md`・講座の規約と教訓ファイル・講座の slide-reviewer の観点）。
> 各節は、ある講座の直近14本のレビューの高・中を手で分類した**頻度の高い順**。件数は「指摘数／本数」の目安。
> 道具はプラグインの `scripts/`（`python "${CLAUDE_PLUGIN_ROOT}/scripts/<名前>.py"`）。**パイプラインのスクリプトに `--help` を渡さない**（`audio.mjs` は本処理が走る）。

## 1. 台本の関門（音声を作る前に済ませる）

**書く前**
- [ ] **用語集を先に決める。** 同じものを指す語はレクチャー内で1つにする。兄弟ユニット・冒頭・末尾の `SCRIPT.md` を先に読み、用語の定義の言い方（「〇〇＝△△するためのルール」）と**説明の筋**（理由の順・例の運び）も兄弟とそろえる。全部書いたら、同じ対象を指す語を grep で並べて見る（13件／7本。`quality-standards.md` 36）
- [ ] 事実は講座の事実の正本の範囲だけ。「よく問われる」など**頻度・特性の断定は正本に書いてあるときだけ**。範囲外の語・手法名は出さない。正本で未決の事実は断定しない。機能の状態（プレビュー・終了）を語るときは状態を言う（`product-status.md`）
- [ ] **字数の上限を先に決める**: 1ユニット 1500〜1850字、冒頭 150字前後、末尾の1行は 200字以内。レビュー反映のたびに +100〜200字ふくらむので、上限に着いたら詰めてから反映する（`quality-standards.md` 25）。尺は見積りで削らず音声後に決める。レクチャーは30分を超えたら分ける
- [ ] **例の数は Python で検算**し、設計メモに残す（足して100・割った値・小数）。説明用の例と画面にも断る
- [ ] **画面の割り当てを決める。** 機能紹介・使い方の行は、どの枚にどの画面（実機かドキュメント）を載せるかを設計メモに書き、音声の前に撮る（`quality-standards.md` 29・`slide-format.md` §2g）

**書いた後（やってはいけない型。頻度順）**
- [ ] **定義前の用語を使わない**（15件／10本）。初出で一言の定義か例を添える。別レクチャーの語の先出しも同じ。定義文は**対象を限る**（一般形で言うと別の手法まで含んでしまう。8件／7本。`quality-standards.md` 8）
- [ ] **理由・つなぎの1段を抜かない**（13件／9本）。結論だけ渡さない（なぜ似ていると言えるか、なぜその値を最大にするか、なぜ組み合わせると出せるか）。例を替えるときは橋渡しを1文。例が主張を見せているか確かめる
- [ ] **1行に詰めない**（12件／11本）。新語・定義・数・条件を1行に重ねない。長ければ行を分ける（音声前なら番号の振り直しは無料）。指摘された長さの実績: 196字・269字・353字の行
- [ ] **考えてみよう**（11件／10本。作り方は `quiz-authoring.md`）
  - 問いは、しくみで見せた数・絵・言い回し・場面の言い換えで解けない
  - 選択肢を書いたら表にする（語尾・字数・理由の句の有無・問いの語が出るか・直前の行の否定か・問いの条件と字面で食い違うか）。正解だけが違う列、正解が誤答の要素の和になっている列があれば作り直す
  - ひっかけは問いの前に言わない（答えの行で言う）。誤答を「直前の行の文の否定」で作らず、2フレーム以上前の事実どうしの取り違えで作る
  - 手法を「1つ目／2つ目」と数えたユニットでは、選択肢を番号で言わず内容で言う。番号で言うなら「ひとつ目」と区切る
  - 場面を曖昧にしない。決め手の材料はしくみの中で先に言う。問いの最後は「少し、考えてみてください。」。答えは理由まで
- [ ] **試験の点・要点を落とさない**（6件／5本）。ユニットで「問われる」と言った点は要点と末尾に入れる。ひっかけ（誤答の定番）は正しい定義とセットで言う。地図・詳細・要点の名前をそろえる
- [ ] 数の言い方: 変わる前の値を言ってから変わった値を言う（「上は30から25」）。小数・英字の羅列は画面に任せ、語りは言い換える（`tts-readings.md` C2）
- [ ] 画面に出る語（表の中身・見出し・数字）は語りで読む。読まない語は絵に出さない
- [ ] 体言止めを避け、述語で言い切る。名詞の列挙は1文に。続きを予告して終わる行を作らない
- [ ] 「数」の単独使用（かず／すう）と同音異読の語（止める・後・方・節）を避ける。TTS が誤読する名前は、名前を教える所以外で言い換える（`tts-readings.md` C9）
- [ ] **英字の語の読みは台本で決める。** 誤読が疑わしい略語は scratch で `tts.py --only` を試作し、`hira_check.py` で確かめてから綴りを決める（決めた綴りは報告へ。`tts-readings.tsv` は親が足す）
- [ ] 舞台裏の語を出さない: 受講者/講師/番号/ユニット/フレーム/digest。出どころの断りを入れない（講座の方針。`quality-standards.md` 11）。別レクチャーへ約束しない。**最後の行は「次は…」**（「次のレクチャーでは」と書かない）
  - 確認: `grep -nE '受講者|受講生|講師|[0-9]-[0-9]-[0-9]|ユニット|フレーム|digest|設計書' videos/<unit>/SCRIPT.md`（字下げ行に0件）
- [ ] **初学者役レビューと事実の照合**を通し、**日本語構成チェック**（`japanese-check.md`）を通した

## 2. 音声の関門（音声は再現できない）

- [ ] **台本の初学者役レビューが済んでから**音声を作る。音声のあとに直すと録り直しで語末が全部ずれる
- [ ] `export PYTHONIOENCODING=utf-8`。`tts.py videos/<unit>` を**1本ずつ前景で**。直す行は `--only N`（先に scratch）。**`--only` なしで再実行しない**（既存の音声が作り直され、尺と語末がずれる）
- [ ] 作った直後の退避は `tts.py` が自動で行う（`<audio_backup_dir>/<日付>/<unit>/after-tts/`）。退避があることを確かめる
- [ ] 台本の順序を変えるときは、wav を後ろからリネーム→`audio_meta.json` の `frame`/`path` を直す→`--only`
- [ ] 直後に `check_reading.py videos/<unit>`。一致率と付加・脱落・2回読みの兆候を**書き起こしで読む**。本物なら該当行だけ `--only`
- [ ] **英字・同音異読の語を含む行は `hira_check.py` で音を確かめる**（`check_reading.py` は漢字・かなだけを比べるので英字の誤読が出ない。Cloud STT は英字の多い行の後半を落とすことがある）
- [ ] 録り直すのは、疑う読みが過半数のときと文の脱落・付け足しだけ（`tts-readings.md`「読みの確認を過剰にしない」）
- [ ] 誤読は `redo_until.py <unit> <frame> --need 語 --ban 誤読の綴り`。読めた時点で止まる。**`--need` に同音語を入れない**（STT が同音で返し空回りする）。`--need` は別の語に化けていないことの確認に使う
- [ ] 数量の「数」（かず／すう）は STT で区別できない。耳で確かめる語として報告する
- [ ] 順に: `pad_audio.py`（行頭0.6秒・行末1.2秒。冪等）→`check_clicks.py videos/<unit> --wav-only`→`make_beats.py`→`audio.mjs sync-durations`（**このサブコマンドだけ**。他のサブコマンドを試さない）→`dump_beats.py`。作り直したら全部やり直す
- [ ] `word_times.py` の誤読の警告を見る

## 3. スライドの関門

型は `unit-playbook.md`（F1 現在地→場面→地図→使いどころ→しくみ→長所・弱点→考えてみよう→要点→試験と次へ）。**他ユニットの絵を流用せず、内容ごとに設計し直す**。

- [ ] **近接・行間**（26件／12本・最多）。積んだ行は行送り1.4倍以上（式・データの短い行は1.25〜1.3倍）／まとまりごとにカード、余白 8・24・64px、**外側＞内側**／左右のガターは約100px（本文の2倍）／大きさは1枚3段まで・太さ400/700の2種／意味の違う色は3色まで／橙の注を式のすぐ下に付けない／**同じ型が3つ以上続くなら、終わったものを1行に畳む**（`slide-format.md` §2e）
- [ ] **枠・丸・矢印が文字に触れない**（16件／9本）。札の高さは文字の高さ＋上下の余白（隙間8px・余白9pxはNG）、丸は文字より大きく、矢印は数字の手前で止め（20px以上）、枠の端に最後の字を詰めない
- [ ] **表示は話し始めに**（16件／12本）。`E(frame, "語")` は語末なので、長い説明の行には**発話の最初の語**を渡す。同じ語が複数あるときは `E(f, "語", n)`。**全 `E()` の出現位置を表にして突き合わせる**（`check_late_reveals.py` は変数渡しや別出現の誤引きを拾わない。`check_nth.py` で同じ語の回を見る）
- [ ] 読んでいる語が画面にある／語りの**肝の一文**が画面に無い時間を作らない／語りが長く続くのに画面が増えない時間を作らない（先頭の6秒がタイトルだけ、も NG。実践の本体は例外。`slide-format.md` §9）
- [ ] **意味の分からない図形を作らない**（13件／9本）。図形・棒・色・丸／四角には名前か凡例を付け、初出の枚で読む。形の意味は1つ。「A≠A」に見える左右の同じ札、軸や十字に見える図、事実の否定に付けた × に注意
- [ ] **箱は図だけ。** 名前・説明・要点は箱にせず、タイトル直下の文（`lead`）かテキストに（5件）。**中身の無い箱・図形を先に出さない**（箱は中身の語と一緒に、その語を読んだとき）。半分空のカード・途中で下が空の枚を作らない（6件）。タイトルと解説文を言い直しにしない（4件）。枚の最初の行にタイトルの語を使わない（`quality-standards.md` 35）
- [ ] **数や座標で主張する絵は計算して `slides.py` に `assert`**（行列の積・最近点・棒の長さ＝数。5件）。目で置かない
- [ ] 設計メモで決めた表記（ギリシャ文字・英字／カタカナ）と画面を合わせる。画面の語もそろえる（地図・要点・現在地の名前）
- [ ] 図は画面を使い切る（`layout.safe` x40→1880 / y40→1040）。小さい図＋半分空にしない。主役の字を脇役より大きく
- [ ] **書体に無い字**: → は `s.arrow`、✓ は `s.check`、✗ は `s.cross`、★ は多角形。ギリシャ文字は代替フォントで出るが**読みを添える**。幅の検算 `Fonts.width` は1em の仮置き
- [ ] 画面のキャプチャの枚: 塗り残し 0 件・切り出しが語る句を含む・枠は切り出しの画素の座標（`slide-format.md` §2g）
- [ ] reveal は1フレーム最大6回、フェード開始は0.5秒以降。動きはフェードと矢印の描画だけ。数値の例には画面にも「例」と出す
- [ ] 検査は次の順に回す（`export PYTHONIOENCODING=utf-8`）。
  - `unit_build.py <unit>`（**Chrome を起動する**。lint・check・継ぎ目・snapshot）
  - `check_idle.py`・`check_late_reveals.py`・`check_nth.py`・`check_spacing.py`（候補を1件ずつ判断。直すか、意図した詰めと決める）
  - `check_coverage.py videos/<unit>`（`fill` が100%超なら尺の外を撮っている）
  - `check_quiz_words.py videos/<unit>`（★が正解の選択肢なら作り直す）
  - `sheet.py <unit> <フレーム…>` → `.hyperframes/sheet.jpg` を**画像として読む**（開始直後・途中・着地。抜き取りにしない）
  - `slide_table.py videos/<unit> --write <doc>`

## 4. 止まる所と報告の形

- [ ] **A 台本**: 設計メモ＋`SCRIPT.md`を書いたら止まって報告（音声は作らない）→親が初学者役レビューと事実の照合
- [ ] **C 制作**: レビュー指摘を台本に反映→日本語構成チェック→音声→slides→自分で目視。build と目視が通ったら止まる→親が slide-reviewer
- [ ] **D 修正**: 高・中を直し（録り直しを含む）、再ビルドして報告。**レンダリング・`make_srt`・`make_lecture` は親**
- [ ] 報告は短く。A: 設計メモ（使いどころの場面・しくみの具体例・考えてみようの問いと答え・選択肢の表・地図の行）／台本の場所／迷った点。C・D: 完成したか／尺／フレーム数・ページ数／各検査の結果／直したもの／**直さなかったもの（理由つき）**／**耳で確かめる語**／`slide_kit` に欲しい機能

## 5. 記録・共有物・運用

- [ ] 講座の教訓ファイル（`self-improvement.md` §2）は**親が書く**。踏んだ失敗・直さないと決めた裁定は、最終報告に「何が起きた／直し方」を1行で書く（0件でも「なし」）
- [ ] 触らない: プラグインの `scripts/`・講座の部品・講座の `CLAUDE.md`・引き継ぎ文書・`.claude/*`・他ユニット・`tts-readings.tsv`（欲しい変更は報告に書く。自分の `slides.py` 内の部品は可）
- [ ] **サブエージェントは起動できない。** レビューは親が回す
- [ ] ブラウザを立てるコマンド（`unit_build.py`・`npx hyperframes check/snapshot/render`）は**1人あたり同時に1本**。重い処理の並べ方・プロセスの止め方・Windows の書き込みの失敗は `windows-and-ops.md` §1〜3
