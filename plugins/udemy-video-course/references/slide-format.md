# スライド型 — 動きを減らし、資料として読める動画にする（Hyperframes）

Hyperframes で1枚ずつ絵を描き、語りに合わせて要素を出す座学の型。2つの講座で承認され、新しいユニットの標準になった。
実践（ハンズオン）の本体も同じ型で組める（§9）。

- 部品と規則の強制は `slide_kit.py`。ユニットの手順は `unit-playbook.md`、関門の一覧は `production-checklist.md`
- 台本・スライドの品質の基準（話の順に出す・箱は図だけ・固有名を言い換えない など）は `quality-standards.md`。ここは**型**（画面・時間・ページの組み方）を持つ
- 色・書体・白地の正本は各ユニットの `frame.md`（雛形は `course.yaml` の template_dir）。動きと間の正本はこの文書
- 講座が別の型の文書を使うときは `course.yaml` の slide_format_doc に書く（`make_unit.py` が BRIEF に書き込む）
- **型を変えるときは、この文書・`slide_kit.py`・講座の規約・`frame.md` を同時に直す。** 1か所にしか書かないと、次のユニットで動きが戻る

## 1. 何を直すのか

制作者に次のように指示された。

> 「Hyperframes でかなり動きのある動画を作ってたと思うけど、あれだと受講者が疲れると思う。もう少しだけスライド資料っぽい感じにして。中身を解説するときには、今のような図解ベースの解説は必要。」

**疲れる原因は、図の大きさでも図解の量でもなく、フレームの中で絵が動き続けることだった。**
だから図は大きいまま・画面を使い切ったままにして、**動きと切り替えを離散化**する。

**やらないこと**（過去の指摘に逆行する）
- 図を小さくして周りに余白を作る（占有率の指摘が2回あった）
- 画面に文章・箇条書きを足す（画面はラベルと要点だけ。逐語は語りが担う）
- 色や書体を変える（`frame.md` のトークンをそのまま使う）

## 2. 画面の型

```
┌──────────────────────────────────────────────────────────┐
│ ▍タイトル（常設・5.0cqw・太字）             [並列] ■□□ │  ← 進行札（右上・数字を使わない）
│ 解説文（タイトル直下・小さめ・最初から表示）               │
│                                                          │
│                     本体（図解）                          │  ← y 210〜1040。safe いっぱいに使う
│                                                          │
└──────────────────────────────────────────────────────────┘
```

| 部品 | 規則 |
|---|---|
| **タイトル** | **常設・空にしない。** 左に青の縦棒、その右に太字。1〜14字。語りの文ではなく**名前**を置く（`Slide(title=...)` が空を拒否する） |
| **進行札** | 右上。黒の丸札（枝の名前）＋小さな四角の列（現在位置だけ黒）。**数字は使わない**（台本に数値が無いため）。枝を持たない枚（導入・全体像・まとめ）は出さない |
| **本体** | 図解が主役。**箱・図形は中身の語と一緒に、その語を読んだときに現れる**（§3-2） |
| **解説文** | タイトル直下に、その枚の内容を**一文で説明する文**（3.2cqw・太字にしない・1行 28字前後まで）を**最初から表示**する（リビールしない）。語りの丸写しにしない。**タイトルにも図にも無い情報（定義・理由・関係・帰結）がある枚にだけ置く。言うことがなければ置かない**（「タイトルと解説がほとんど同じ」と指摘された）。実装は `slide_kit.lead()` |
| **箱** | **箱は図（対象・器）だけ。** 名前・説明を箱にしない（「下の箱は図解というより説明」と指摘された）。説明は解説文に置く |
| **色の役** | `ink` = 文字 ／ `subj`（青）= 主役の図 ／ `acc`（橙）= **その枚の強調1対象**（重複・間違い・残差・キーワード）／ 面は `face` `subj-face` `acc-face` |

- 文字は 1.35cqw（26px）未満を使わない。`s.text(..., fit=幅)` が枠を超えると例外になるので、短くするか小さくする
- 同梱の書体（BIZ UDPGothic の日本語サブセット）に `→` `✓` `✗` `★` は無い。`s.arrow`・`s.check`・`s.cross`・多角形で描き、文字で書かない（`quality-standards.md` 23）。`…` `・` `「」` と ASCII の英数字・記号はある

## 2b. 教材ページ

ユニットは「**教材ページ → 図解の詳細 → 教材ページ（要点）**」で組む。教材ページが地図、図解が中身（「教材感を。解説文章もつける」と指示された）。

- **全体の地図（詳細の前）**: 「〇〇の3つの問題」のように、そのユニットで扱う語を**行の一覧**で出す。各行は「名前＋短い解説文」。
  行は**始めから薄い色で全部見えている**。語りがその行に来たら、行が**青い面＋濃い文字で強調**される（強調は残る＝進み具合が見える）。
  語りは「ここで見ていくのは、3つです。…ひとつずつ、順に見ていきましょう」（§3-9 の全体像を兼ねる）
- **要点（締めの直前）**: 同じ行の型で、行に ✓ が付く。全体像の図は描き直さない
- **解説文は、その枚の語りで読む語だけ**で書く（§3-8）。1行 20 字前後まで
- 実装は `slide_kit.lesson_rows()`。薄い行の上に強調の行を重ねるので、文字に `overlap=True`（`data-layout-allow-overlap`）を付ける。
  薄い行と強調の行は同じ太さで描き、濃さだけを変える（細字と太字を重ねると字送りがずれて二重に見える。`quality-standards.md` 21）
- 英字の名前は幅を取る（12字の英字の製品名が 4.6cqw で約 630px）。名前の欄を `lesson_rows(..., split=860)` のように広げる（既定の 720 だと `fit` の例外で止まる）
- 図解の枚も教材ページも、タイトル直下に解説文を置ける（§2 の「解説文」）

## 2c. ページ

**語りの1行＝1フレーム（音声・語末の単位）は変えない。関連する数行を1枚（ページ）として続けて見せる**（「スライドの移り変わりが多すぎる。1枚の情報量を多く」と指示された）。
1ユニット 10行 → **4〜6ページ**が目安。

- ページの中では、前の行の図は**着地した姿で最初から見えていて**、その行の図だけが語りに合わせて足される
- 切り替えは**ページの先頭だけ crossfade 0.5s、ページの中は cut**（前の枚の終わりと同じ絵から始まるので継ぎ目が見えない）
- まとめ方: 導入（問い→別の問題）／分かれ目＋地図／詳細のうち同じ問いに答える行（例: 3つの種類を3段の表に）／要点＋締め
- **無関係な2つを1枚に押し込まない。** 冒頭・末尾は1行がもともと教材ページ1枚なので、まとめない
- ページの途中で教材ページ（地図）を出すときは、薄い行も語末でフェードさせる（`lesson_rows(show_at=...)`。cut の瞬間に現れない）
- 実装は `slide_kit.render_pages(UNIT, D, PAGES, out)`。`PAGES = [(タイトル, 解説文, [(フレーム番号, id, 描く関数), ...]), ...]`。
  **STORYBOARD の voiceover・scene・transition_in も render_pages が合わせる**（手で直さない）。
  前の行の図は `s.past()` の中で同じ関数を呼んで静止で描く（`reveal` が動きを作らない）
- ユニット doc の §5（絵と語りの対応表）は手で書かず、`slide_table.py videos/<unit> --write <doc>` で作った slides から書き出す（手で書くと slides.py を直すたびに食い違う）

## 2d. 1ユニット＝1レクチャー

制作者の指示:「レクチャーがてんこ盛りすぎ」「セクション全体のうち何についてのレクチャーか、進捗が分かることが大事」
「どういうときに使うのかをイメージできたり、処理の詳細を解説したり、理解度を深める工夫を。表現は内容に応じて柔軟に」。

- **F1 現在地**（`slide_kit.position_map`）: 左に章のまとまり、右にいまのまとまりのユニット（済み ✓・いま 青）。
  GROUPS は**そのまとまりが属する章のまとまりの名前**（章のレクチャー名など）、UNITS はそのまとまりのユニット名。
  **例外**: まとまり・ユニットの名前は語りで全部は読まない（区切りの札と同じ扱い。全体のどこかを示すのが目的）
- 構成: 現在地 → 場面（なぜ要るか）→ 地図 → **使いどころ** → **しくみ**（具体例で1段ずつ）→ 長所・弱点 → **考えてみよう** → 要点 → 試験と次へ
- **考えてみよう**: 問い → **無音の「考える時間」フレーム**（6秒・絵は止めたまま。§3 の「無音の枚を置かない」の例外）→ 答えと理由。
  **しくみのページと同じ数・同じ絵を問いに使わない**（記憶で答えられてしまう）。問いと選択肢の作り方は `quiz-authoring.md`。
  選択肢の番号は、語りは「ひとつ目、ふたつ目、みっつ目」、画面の札は「1」「2」「3」にしてよい（講座の方針。語りと画面の表記が違っても「読まれない語」として扱わない）
- 試験の点は、要点の行に「試験」の札を語りに合わせて付ける（読んでいるのに画面が無い時間を作らない）
- 形の意味を1つに保つ（丸＝ある群・四角＝別の群なら、ほかの用途に同じ形を使わない）
- **尺は約4〜5分（1500〜1850字）。** 内容の量に合わせ、**概念が少ないのに水増ししない**（概念が2つ以下なら、使いどころと分かれ目を1枚にまとめる。`quality-standards.md` 26）。
  1ページあたりの量は §2c の4〜6ページではなく、内容のまとまりで決める。レクチャー（冒頭＋ユニット＋末尾）が30分を超えたら分ける

## 2e. 見やすさ（デジタル庁デザインシステムから取り込んだ規則）

内容が正しくても「見にくい」と差し戻された枚（式3つを行間 1.13 倍で積み、大きさ3種・色3色を混ぜた）から、
デジタル庁デザインシステム（https://design.digital.go.jp/dads/foundations/ のタイポグラフィ・カラー・スペーシング・レイアウト・角の形状）の数値を取り込んだ。
要約は `quality-standards.md` 20。ここはスライド型での運用の数値。色・書体の正本は `frame.md` で、食い違えば `frame.md` が勝つ。

**1. 近接（いちばん効いた）**
- 関係の近いものは近く、遠いものは遠く。区切りは線でなく**余白の差**で作る
- 間隔は 8px を単位にした段にそろえる。基本は **8 / 24 / 64 px**（行の中 / カードの間 / 大きなまとまりの間）。1px ずつ違う余白を作らない
- **まとまりの外の余白 ＞ まとまりの中の余白。** 逆になると別のまとまりに見える
- 見出しの余白は見出しの大きさに比例させる（大きい見出しほど上を空ける）
- 入りきらないときは、**文字を縮める前に、畳む・分ける・減らす**

**2. 行間**
- 積んだ行の行送りは**文字の高さの 1.4 倍以上**。データ・式の短い行だけ 1.25〜1.3 倍まで
- 行送りは2行の文字の大きさの平均で測る（`check_spacing.py`）
- 字間は BIZ UDPGothic の既定のまま（いじらない）
- 階層は大きさと太さの差ではっきり付ける。**太さは 400 / 700 の2種**だけ。斜体は使わない
- 大きさは**1枚に3段まで**（見出し・主役・本文）。3.0 と 3.4 のような近い大きさを混ぜない（どちらが上か分からなくなる）

**3. 色**
- 1枚で**意味の違う色を3色以上使わない**（青＝名前・主役・いま見ているもの、黒＝本文、橙＝ひっかけ・失敗、灰＝終わった・背景）
- 本文の文字は背景に対して 4.5:1 以上、隣り合う図形は 3:1 以上。色の付いた面の上の文字は、その面の上で測る（`hyperframes check` のコントラストが見る）
- **色だけで区別しない。** 橙の注には「誤り：」のように語でも区別できる書き方をする
- 橙の注を式のすぐ下に付けない（式の一部に見える）

**4. レイアウト**
- 左右に分けるときのガター（間）は本文の文字の2倍以上（約 100px）。どちらが主役かを位置と大きさで決める（主役は大きく、脇は畳む）
- 角の丸みは図形の大きさに合わせる。`rect` の既定 `r=12` はカード・箱、小さな札は `r=8` まで
- 図は画面を使い切る（`layout.safe` x40→1880 / y40→1040）。小さい図＋半分空にしない。主役の字を脇役より大きく

**5. 畳む**
- 同じ型のまとまりが3つ以上順に出るとき（指標を3つ・手法を3つ）、**終わったものは名前＋結果の1行カードに畳み、いま見ているものだけを展開する**。最後に3つの要約が並び、まとめにもなる
- 畳むのはフレームの境目（語りの前後の無音のとき）。前のフレームの絵は `past()` の静止描画で作る（`s._static` のとき要約を描いて `return`）

**取り込まなかったもの**: 本文 16px 以上（動画は 26px 以上と決めてあり、より厳しい）／書体の指定（UD 書体を同梱している）／グレーの段階（白地・1色・薄い面の方針が `frame.md` にある）／フォーム部品の指針（動画に無い）

検査: `check_spacing.py videos/<unit>` が、同じ列に積んだ文字の行送りが 1.25 倍未満（文の行どうしは 1.4 倍未満）の組を**候補**として出す。
「見出し＋数」のような意図した詰めもあるので、直す（行を離す・カードに分ける）か、意図した詰めと決めるかを目で見て決める。
直すのは「同じ列に3行以上積んだ文章・式」「別のまとまりなのに同じ行送りで続いているもの」。

## 2f. 末尾の「試験で狙われる点」の型

点が多い（正しい点とひっかけが計10行以上）ときは、**前置き1ページ＋点ごとに1ページ**（行は薄く始まり、語りが来た行が点灯。正しい点は青の ✓、ひっかけは橙の ✗）。
4点が1ページに収まるときは1ページのまま。
冒頭の「流れ」は、語りが1つずつ読むときは**読む順に1行ずつ青くし、最後に1行目へ戻す**。1行目だけをいまにする型でもよい。

## 2g. 画面のキャプチャを載せる枚

機能紹介・使い方の説明には、座学でも実際の画面を載せる（図だけの枚で機能を説明しない。`quality-standards.md` 29〜33）。スライド型での置き方は次のとおり。

- 撮った画面は塗ってから（`ocr_mask.py` → `leak_check_ocr.py`）、語る部分を切り出してユニットの `assets/` に置く。切り出しの座標はスクリプトに残す
- 画像は**比率のまま**置き、強調の枠は**切り出しの画素の座標**で当てる（`meet` の余白で枠がずれない）。置く関数は講座の部品（`course.yaml` の parts_dir の `*_parts.py`）に1つ作り、全ユニットで使う
- ドキュメントの画面は、語る1〜2行だけを切り出して 2〜3 倍で置く（広く切り出して小さく置くと字が読めない）。表は見出しの行を含める
- 切り出しの寸法を変えたら、置く幅と下の要素の y を計算し直し、途中と着地のスナップショットを原寸で見る
- 同じ場所に描き直すと前の枠が消える。薄い面の上に描き直すときは白の面を先に敷く（面が透ける）
- `slides.py` を書く前に、切り出しが語りの頼る句を含むか・語らない文（選択肢を先に否定する文など）を含まないかを画像で見る
- **台本の段階で「どの枚にどの画面」を決め、音声の前に撮る。** 後から差し込むと、既存のリビールの数・位置に押し込むことになる

## 3. 時間の型（モーション契約）

**これが型の本体。** すべて `slide_kit.py` が**コードで強制**する（守らない絵を書けない）。

1. **切り替えは `crossfade 0.5s`（先頭の1枚だけ `cut`）。** `push-slide` は使わない（0.2 秒は「速すぎる」と指摘された）。
   **枚どうしで要素を共有しない。** 切り替えの窓（先頭 0.5 秒）では何も動かさず、
   `slide_kit` が**最初の動きの開始が窓より後**であることを検査する（違反すると生成が失敗する）
2. **中身の無い箱・図形を先に出さない。箱や図形は、中身の語と一緒に、その語を読んだときに現れる。**
   （「音声では読んでるのに文字が表示されてないし、そもそも図形だけ最初に表示されてるのおかしくない？」と指摘された。何の箱か分からない図形が先に出るほうが不自然だった）
   - 切り替わった瞬間に見えているのは**タイトル（と解説文）**。本体は最初の語で現れる
   - **読んだ語は、読んだときに画面に出す**（読み終えたあとにまとめて出さない）。列挙は1語ずつ
   - 例外: 前の枚から引き継ぐ**中身つき**の要素（ラベルの入った箱など）と、教材ページの行・流れの一覧（文字が入っている）は始めから見えてよい
3. **動きは2種類だけ。**
   ① **リビール** = 不透明度 0→1 のフェード、**0.4 秒**
   ② **矢印の描画** = 線が **0.5 秒**で伸び、矢じりが最後の 0.1 秒で現れる。
      **矢印だけ**（木の枝・数直線・枠は描かない）。先の要素が現れる**前に**描き終える（`lead=True`）。
      群の中の要素から出る矢印だけ、群のフェードと同時に描く（`lead=False`）
   **移動・拡大縮小・回転・色の連続変化・idle・揺れは置かない。**
4. **リビールは語の語末に着地する。** フェードの開始 = 語末 − 0.4 秒。矢印の描画は、その手前（`lead=True` なら語末 − 0.9 秒）。
   語末は `word_times.py` の実測（**終了時刻だけ**を使う）。ただし長い説明の行は、文末の語ではなく**発話の最初の語**に着地させる（`unit-playbook.md`「表示は話し始めに」・`quality-standards.md` 15）
5. **1枚のリビールは最大6回**（通常は 2〜4。**列挙を語の順に1つずつ出す枚だけ 5〜6**＝全体像の手法名・冒頭のアジェンダ）。
   同時に出す要素は1リビールにまとめる（並列 = **同時に出る**、直列 = **1つずつ出る**、で意味を運ぶ）
6. **最後のリビールの後は完全に静止する。**
7. **切り替えに「間」を作る**（「移り変わりが速すぎる」と指摘された）。
   **行頭 0.6 秒・行末 1.2 秒**の無音を `pad_audio.py` で足す（発話のバイトは変えず、ゼロを前後に足すだけ。TTS は作り直さない）。
   語り終えてから次のスライドが見え始めるまで**約 2 秒**、次の語りが始まるまでさらに**約 0.6 秒**。
   手元の確認用の字幕（`make_srt.py` の `.srt`）は `head_s` / `tail_s` を読み、語っている間だけ出す。字幕を公開先に上げるかは講座が決める（既定は上げない）
8. **絵に出る語は、すべて語りで読む**（「読まれていない内容がある」と指摘された）。
   無音のスライドに文字を出さない。読まないなら、その語は絵に出さない
9. **全体像は詳細の前に置く**（「全体像を先に、そのあと詳細を順番に」と指示された）。
   枝が2つに分かれると告げた**直後**に、全体像のスライドを置いて語を1つずつ読み、
   **「ひとつずつ、順に見ていきましょう」で締める**（ワンクッション）。詳細のあとに同じ全体像を再掲しない
10. **強調は色で行い、動きでは行わない。** 焦点は `acc` の1対象。

## 4. 作り方（ワーカー不要）

```
台本（SCRIPT.md）→ 初学者役レビュー → 日本語構成チェック → tts.py（直す行は --only。作った直後に自動で退避）
  → check_reading / hira_check → pad_audio → check_clicks → make_beats
  → new_storyboard → sync-durations → dump_beats → slides.py（生成元）
  → unit_build.py（compositions/frames/*.html → assemble-index → transitions inject → lint / check → check_crossfade → snapshot）
  → check_idle・check_late_reveals・check_nth・check_spacing・check_coverage → sheet → slide-reviewer
  → render_units.py → make_lecture.py
```

- 道具はプラグインの `scripts/` にある（`python "${CLAUDE_PLUGIN_ROOT}/scripts/<名前>.py"`）。手順の詳細は `unit-playbook.md`
- **`slide_kit.py`** = 部品（タイトル・進行札・矢印・札・リビール・教材ページの行・現在地）。型の規則をここで強制する
- **講座の部品** = `course.yaml` の parts_dir の `*_parts.py`（画面の置き方・選択肢の札など、その講座の全ユニットで使うもの）。`unit_build.py` が PYTHONPATH に入れる
- **`videos/<unit>/slides.py`** = そのユニットの中身。**語末は手で書かず**、`_beats.md`（`make_beats.py` の実測）から `E(frame, "語")` で引く（音声を作り直したら `make_beats.py` を回すだけで追従する）
- **HTML は直接直さない**（生成物）
- 枚を並列ワーカーに配らない。共有ステージの契約・寸法の配布・crossfade の整合が要らないので、**1人で1回で書ける**
- Hyperframes の版は `course.yaml` の hyperframes_version に固定する（`unit_build.py`・`render_units.py`・雛形の `package.json`）。上げるときは1本で lint・check・snapshot・render を通してから
- `assemble-index.mjs`・`transitions.mjs`・`audio.mjs` は faceless-explainer のスキルのもの（`course.yaml` の faceless_scripts）

## 5. 実測の目安

型どおりに作ったユニットで出る値。外れたら原因を見る。

| 項目 | 目安 |
|---|---|
| 占有率 `fill`（`check_coverage.py`） | 85〜98%。100% を超えたら尺の外を撮っている |
| リビール | 1枚 2〜4 回（列挙の枚だけ 5〜6） |
| `hyperframes lint` / `check` | 0 error 0 warning。コントラストは全数 WCAG AA。Layout の info は、クロスフェード中に前後の文字が重なる意図どおりのもの |
| `check_crossfade.py` | ERROR 0。REVIEW は「矢印の `strokeDashoffset: 1` が t=0 に書かれる」（見えない状態）だけなら問題ない |
| クリック（`check_clicks.py`） | 0 件 |
| 間を足した尺 | 間の無い版より、行あたり約 1.45 秒伸びる（行頭 0.6 ＋ 行末の増分 0.85。`tts.py` が行末に 0.35 秒を足してある） |

## 6. 規則と検査の対応

| 規則 | 強制・検出 |
|---|---|
| タイトル常設・動き2種・リビール6回まで・窓で動かさない | `slide_kit.py`（守らないと生成が失敗する） |
| 文字の収まり | `s.text(..., fit=)`（同梱の書体で実測。例外で止まる） |
| 前後の枚の二重表示 | `check_crossfade.py`（`unit_build.py` が回す） |
| 読んでいるのに画面が増えない・タイトルだけの時間 | `check_idle.py` |
| 表示が話し終わりに出る | `check_late_reveals.py`（遅いほう）・`check_nth.py`（同じ語の別の回を引いた早いほう） |
| 行送りの詰まり | `check_spacing.py` |
| 図が画面を使い切っていない | `check_coverage.py` |
| 考えてみようが字面で解ける | `check_quiz_words.py` |
| 着地の絵の欠陥（空の箱・読まれない語・偏り） | `sheet.py` のコンタクトシートを全数見る・slide-reviewer（エージェント。講座の追加観点は `.claude/slide-reviewer-extra.md`。制作者の指摘をその場で観点に足す。`self-improvement.md` §3） |

## 7. つまみ

**決まっている値**

| つまみ | 値 |
|---|---|
| 動きの温度 | フェード＋矢印の描画（「フェードだけ」より一段動かす） |
| 切り替え | crossfade 0.5 秒（ページの先頭だけ） |
| 進行札 | 枝のある枚だけ |
| 無音の枚 | 置かない（全枚が静的な型では「1本に1回は無音の静止」の根拠が消えた）。例外は考えてみようの考える時間 |

**動かすなら**

| つまみ | 今の値 | 動かすなら |
|---|---|---|
| 間の量 | 行頭 0.6 / 行末 1.2 秒 | 「まだ速い」なら行末を 1.6〜2.0 に、「間延びする」なら 0.9 に。`pad_audio.py` は冪等なので、**元の音声（`<audio_backup_dir>/<日付>/<unit>/pad-before/`）に戻して足し直す** |
| リビール回数 | 通常 2〜4 / 枚 | 3 に絞る／列挙は1項目ずつ許す |
| 図解の量 | 図は大きいまま | 1枚の要素数を減らす（分割してページを増やす） |
| 画面内の文字 | ラベルと要点のみ | 要点の一文を足す（語りとの二重表示が増える） |

## 8. レクチャーの冒頭・末尾

- **冒頭**（表紙 → このレクチャーのゴール → このレクチャーの流れ）と**末尾**（まとめ → 試験の出題ポイント）は、**独立した Hyperframes プロジェクト**
  （`videos/lecture-<章>-<レク>-open/` `-close/`）。台本の正本はレクチャー枠の doc（`course.yaml` の lectures_dir の下）。
- スライド型の規則はそのまま使う（タイトル常設・動きはフェードと矢印の描画・**中身の無い箱を先に出さない**・**絵に出る語は全部読む**）。
  **ゴール・まとめ・出題ポイントは、教材ページの行（文字入りで薄く見えている）を読みに合わせて強調する。流れ（アジェンダ）は名前を全部見せ、最後の「まずは〇〇から」で1行目だけ青にする**（読むたびに強調はしない）。
- **ユニットの動画には構造スライド（ゴール一覧・アジェンダ・まとめ一覧・出題ポイント一覧だけの独立スライド）を出さない。** ユニットの締めの一行は残す。
- 連結は `make_lecture.py`（`-c copy`。設定が食い違えば止まる。つなぎ目に間を足さない）。手元の確認用の字幕は各本の長さの累積で後ろへずらして統合する。
- **区切りの札**（講座が使うときだけ。「次から次に進むと分かりづらい」と指摘された講座で入れた）: ユニット2本目以降の前に1枚。
  `videos/lecture-<章>-<レク>-bridge-<N>/` を `make_bridge.py` で作る。タイトルは「このレクチャーの流れ」で固定。本体は冒頭の「流れ」と同じ**縦1列の全部の名前**
  （済み＝✓と薄い文字、「ここまで」の語末で直前が済みに、「次は」の語末で次が青＝いま）。`slide_kit.bridge_rows()`。
  **語りで読むのは2つだが、全部の名前を出す**（冒頭の流れで全部を一度読んでいるので新しい情報ではない。§3-8 の例外）。
  ユニットが約4〜5分で1本＝1レクチャーなら、札は作らなくてよい
- **冒頭の流れ**も縦1列（`agenda_rows()`。2列×3段は読む順が決まらなかった）。最後に「まずは〇〇から見ていきましょう」で1行目を青にする。
- **冒頭の表紙**には「なぜ学ぶか（試験との関係）」と「全体の中の位置づけ」を入れる。**末尾**は全項目を一言ずつ振り返る教材ページ＋出題ポイント（§2f）＋「このあと」（小テストと次のレクチャー）。
  末尾のまとめの語りを、ユニットの要点と同じ文にしない（`quality-standards.md` 37）。
- **このユニットの要点**: 締めの一行の直前に1枚。要点2〜3点の札を語りの順にフェードで入れる。**全体像の図は描き直さない**。

## 9. 実践（ハンズオン）の本体をスライド型で組む

実践の本体も、冒頭・末尾と同じ Hyperframes のユニットで組み、`make_lecture.py` で冒頭・本体・末尾を1本の講義につなげる。
理由: 座学と同じ声・同じ間（行頭・行末の無音）・同じ語末の実測と検査にそろえ、1本の講義を同じ型で組むため。撮影・塗り・強調の目視は `record-practice-screen` のまま。

- 本体のユニット名は `course.yaml` の handson_suffix で終える（`make_unit.py` が実践の doc を作る。Line 1 の雛形は handson_line1）
- **1フレーム＝塗り済みの画面1枚＋強調の枠を一度に1つ。** 2つ目の枠は、画面を描き直してから当てる（前の枠が残らない）。ページは1フレームずつ（画面が変わるたびに 0.5 秒のクロスフェード）
- **タイトルは上端の細い帯、画面はほぼ全面**（「タイトル部分はもっと狭くていい。ハンズオン部分をもっと画面全体になるようにした方が見やすい」と指示された）。
  本体の枚は `render_pages(..., compact=True)`（タイトルは高さ 64px の帯に 2.3cqw）、画面の置き場所は `X, Y, W, MAXH = 40, 70, 1840, 1002`。
  冒頭・末尾（スライド）は大きいタイトルのまま
- 強調の枠の座標は**画面の画素**で書く。置き場所を変えても `slides.py` の枠は直さなくてよい。着地はコンタクトシートで全数見る
- **エディターは窓全体を映し、字は撮るときに大きくする。** 小さく撮って語る部分を切り出して拡大しない（「キャプチャの文字が小さい」→ 切り出して拡大した版を見て「窓全体を映してほしい」と指示された）。
  ブラウザはページの拡大 125% 相当、エディターは字の大きさの設定（エディター・チャット・ターミナル）で大きくする。撮り方の詳細は `record-practice-screen`
- エディターの行に当てる枠は余白を小さく（行の間が約 20 画素なので、既定の余白だと上下の辺が隣の行の消し線に見える）。枠の辺は空いた行か行の間の中央に置く
- **`check_idle.py` の FIRST（ページの先頭でタイトルだけ）の NG は、本体では例外。** 画面はフレームの頭から出ていて、リビールは強調の枠だけなので「タイトルだけ」にはならない。
  語りが画面の一部を指し始めたら、その語で枠を出す（指していない間は枠を出さない）
- 台本は撮れた画面から書く（生成 AI の返答は毎回変わる。`quality-standards.md` 33）。尺は合成済み音声の実尺から決まる（間は §3-7 のまま）
- 仕上げのレビューは `transcript-reviewer`（画面と台本・一次資料の突き合わせ）。冒頭・末尾はスライドのレビュー

## 10. 講座ごとに決めるもの

型は講座に依存しない。講座で変わる値は `course.yaml`（`course_config.py` の DEFAULTS が既定）と講座の規約に置く。

| 何を | どこで |
|---|---|
| 受講者像・置き場所（videos_dir・lectures_dir・template_dir・lectures_out_dir・audio_backup_dir）・章フォルダ（chapter_dirs）・doc の種別（doc_kind_tokens） | `course.yaml` |
| 雛形（`frame.md`・`hyperframes.json`・フォント）| `course.yaml` の template_dir（既定 `videos/_template`）。プラグインの `templates/slide-unit/` から写す |
| 声・モデル・読みの辞書 | `course.yaml` の tts（voice・model・instruction・readings=`tts-readings.tsv`）。辞書の書き方は `tts-readings.md` |
| 音声と照合のクラウド | `course.yaml` の gcp（project・location。空なら環境変数 GOOGLE_CLOUD_PROJECT） |
| ユニット doc の「参照」に並べる資料 | `course.yaml` の doc_refs |
| 事実の正本・範囲外の語 | 講座の規約（一次資料の digest・機能の状態の表。`product-status.md`） |
| 出どころを語るか | 講座の方針（既定は語り・画面・小テストに入れない。`quality-standards.md` 11） |
| 字幕を公開先に上げるか | 講座の方針（既定は上げない。`.srt` は手元の確認用） |
| 区切りの札を使うか | 講座の方針（§8） |
