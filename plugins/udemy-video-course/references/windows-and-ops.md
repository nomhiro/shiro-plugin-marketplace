# Windows と長い処理・ブラウザの運用

Windows（PowerShell と Git Bash）で講座を作るときの運用の決まり。2つの講座（2026-10）で、
止まった・誤報した・化けた事故から決めた。どの講座でも同じなので、講座の教訓ファイルではなくここに置く。

## 1. 長い処理（レンダリング・TTS・STT・ビルド・スナップショット）

1. **Windows の `timeout` は python を止められない。** 長い処理はバックグラウンドで1本ずつ流し、
   完了の通知か、出力ファイルの更新時刻で終わりを見る。止まったら PID を調べて、その PID だけを止める
2. **重い処理は同時に2本まで。** 始める前に空きメモリを見る（空きが 4GB 未満なら待つ）。
   レンダリングは1ユニットずつ前景で回すのが確か。**制作者のほかのアプリ・ほかのセッションは落とさない**
3. **止められた後の報告は、出力の実物を見てから。** 「未レンダリング」「37% で止まった」と2回続けて誤報した
   （実際は数分前に全部終わっていた）。レンダリングの状態を数える道具（講座側の `render_status.sh` など。プラグインには次の版で追加）を、報告の前に必ず流す
4. **音声は1ユニット1呼び出しで回す。** 複数ユニットを1回で流すと、終了の段階で止まった（3時間半・55分）。STT を呼ぶ処理も1本ずつ
5. 重い工程を背景で回すと、止められた後も孤児の python が残る。進み具合はディスクの時刻で見る
6. **バックグラウンドの完了通知を受けたら、すぐ次へ進む**（約3時間止まった）
7. 自分で予約したウェイクアップが、作業が済んだ後に届くことがある。届いたら状態を確かめて「済」と返す。作業が先に終わったら予約を止める

## 2. パスと文字コード

- バックグラウンドの python には**絶対パス**を渡す。出力はパイプで通知に残す
- Git Bash の `/c/...` を Python に渡さない（`C:/...` か相対パス）
- **Git Bash で python の出力が cp932 で化ける** → `PYTHONIOENCODING=utf-8` を付ける。python から python へのパイプも cp932 で化ける
- `Path.write_text` は Windows で CRLF になる。行末を保ちたいファイルは `newline=""` で書く
- **画像・ファイルの書き込みで `Errno 22`（Invalid argument）が出る。** ウイルス対策などが一瞬つかんでいる。少し待って書き直す（3回まで）
- 長いファイル・日本語のパス・バックスラッシュを含む書き換えは、ヒアドキュメントの python でなく、エディタの道具（Write／Edit）で行う。
  シェルを通すとバックスラッシュが1段消え、`"\n"` が本物の改行に、`\1` が制御文字になった
- 別の git の処理が残した `.git/index.lock` で git が止まることがある。その処理が終わってから回し直す（ロックを消さない）

## 3. スクリプトの扱い

- **スクリプトに `--help` を渡さない。** 引数を見ずに本処理を走らせるスクリプトがあり、`audio.mjs --help` が原音声を上書きした。使い方はソースを読んで確かめる
- 繰り返し使う道具を scratchpad に置かない（セッションが変わると消える）。講座の `tools/` か、プラグインの `scripts/` に置く
- 検出器（検査のスクリプト）を作ったら、わざと厳しい閾値で1回回し、出力が出ることを確かめる（写してから一度も働いていなかった検査があった）

## 4. ブラウザ（Claude in Chrome）

- **ブラウザが2つつながっているときは、自分で選ばない。** 一覧を制作者に見せて選んでもらう。名前（Browser 1・2）は入れ替わることがある
- 最初に読み取りを1回して、ログインしているかを確かめる。ログイン画面が出たら、パスワードを入れずに制作者に伝える
- タブグループが見えなくなったら、つなぎ直しを制作者に頼む。**書き込む原稿は、先に手元のファイルに書いておく**（途中で切れても失わない）
- 作業は自分で開いたタブで行い、終わったら閉じる。制作者のタブは使わない（頼まれたときを除く）
- 止める・消す系のボタンが並ぶ所は、縮小なしの画面で座標を読んでから押す（「Keep Working」のつもりで「Stop Now」を押した）
- 入力欄は押してから1文字打ち、入ったかを確かめる。ターミナルではコマンドごとに待つ
- `zoom` の操作で CDP がタイムアウトすると、表示域が縮んで以後の画面が使えない。新しいタブを作り直す
- ページ内スクリプトの1回の評価は約 45 秒で切れる。長い処理は投げっぱなしにして、短い呼び出しで状態を読む
- **OAuth・信頼・Authorize・デバイス認証の承認は制作者が押す**（チャットで許されても、Claude が押すと止められる）

## 5. 自律で進めるときの型

- 区切り（1レクチャーの完成）ごとに、引き継ぎの文書（`NEXT-SESSION.md` など）を書き直す。文脈が要約されても、そこから続けられるようにする
- 区切りの報告は短く: 作ったもの・公開先の状態・反映した改善（1行ずつ）
- 品質の門はレビュー担当。高・中を 0 にしてから次へ進む
- 報告の前に、完成物があることを実物で確かめる
- 本体は計画・レビュー・統合を受け持ち、小さい調査・実装は子エージェントへ渡す。子の成果物は本体がレビューする。
  フォーク（サブエージェント）はサブエージェントを起動できないので、レビューが門の作業は親で回す。レビューは2本ずつに分けて並行で回し、1本ごとにファイルへ書かせる
- ブラウザを立てる担当は6〜8人まで（メモリ）
