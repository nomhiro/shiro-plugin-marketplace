# ユニット制作の手順書（1ユニット＝1レクチャー）— 担当エージェント向け

**最初に `production-checklist.md` を読む**（台本・音声・スライドの関門を1枚にまとめたもの。この手順書は詳細）。

- 型の正本は `slide-format.md`（§2d が1ユニットの構成）。品質の基準は `quality-standards.md`
- 手本は講座の手順書が指す完成済みのユニット（`SCRIPT.md`・`slides.py`・スライドのレビュー結果）。**中身の絵は流用しない**
- 事実の出典は講座の事実の正本（一次資料の digest・機能の状態の表。`course.yaml` の doc_refs）。**コピーしない・範囲を超えない**
- 制作者の要件は講座の `CLAUDE.md` と、制作者の指示の記録。**制作者のレビューでの手戻りを避けるのが最優先**

## 段階（親が段階の境目でレビューを回す。担当は段階ごとに止まって報告する）

| 段階 | 担当がやること | 止まる所 |
|---|---|---|
| **A 台本** | 設計メモ＋`SCRIPT.md`（音声は作らない） | 台本を書いたら止まって報告 → 親が初学者役レビューと事実の照合を回す |
| **C 制作** | レビュー指摘を台本に反映 → 日本語構成チェック → 音声 → slides → 目視 | build と目視が通ったら止まって報告 → 親が slide-reviewer を回す |
| **D 修正** | レビュー指摘の高・中を直す（録り直しを含む） | 直して再ビルドしたら報告。**レンダリングは親** |

**担当はサブエージェントを起動できない／レンダリング・make_srt・make_lecture はしない／共有物（講座の部品・プラグインの `scripts/`・講座の `CLAUDE.md`・引き継ぎ文書・`.claude/*`・他ユニット・`tts-readings.tsv`）は触らない**。
欲しい共通部品は最終報告に書く（自分の `slides.py` の中に書いてよい。`slide_kit` の公開関数は使ってよい）。
段階ゲートで並列に回す理由と上限は `self-improvement.md` §5。

## 型（どのユニットも同じ骨組み。**中身の絵は内容ごとに設計し直す＝他ユニットの絵を流用しない**）

F1 現在地（`position_map`）→ F2 場面（なぜ要るか）→ F3 地図（`lesson_rows` で 3〜4 行・「見ていくのは、Nつです…ひとつずつ、順に見ていきましょう」）→ 使いどころ（具体的な場面）→ しくみ（具体例で1段ずつ。処理の流れが追える）→ 長所・弱点／ひっかけ → **考えてみよう**（問い→**無音6秒**→答えと理由）→ 要点（`lesson_rows(check=True)`・試験の札）→ 試験と次へ。
尺と字数は `slide-format.md` §2d（約4〜5分・1500〜1850字。**概念が少ないのに水増ししない**）。10〜16 フレーム。

### 台本の規則
- 字下げ4スペースの行が読み上げ。見出し `## Line N — 名前 (Frame N)`。**フレーム番号は 1〜N の連番**（無音フレームは番号だけ飛ばす）
- **体言止めを避ける**（述語で言い切る）。名詞の列挙は1文に。質問の引用（「〜か。」）は可
- 事実は講座の事実の正本の範囲。数値の例は**説明用の架空の例**（画面にも「例」と出す）。講座の範囲外の語は出さない
- 地図の行の名前と、要点の行の名前・語をそろえる（地図で言った名前は詳細で必ず出る）。定義も例も無い用語を出さない（初見の語は1文で言い換えるか例を添える）
- **考えてみよう**: 問いは**しくみで見せた数・絵・言い回しの言い換えで解けない**ものにする。誤答の定番（事実の正本の「ひっかけ」）を選択肢に混ぜると良い。問いの**最後に「少し、考えてみてください。」**（無音への合図）。答えは理由まで言う。
  ひっかけは問いの前に言わず、答えの行で言う（誤答が直前に聞いた文の鏡写しになる）。選択肢の作り方と「形で解ける」型は `quiz-authoring.md`
- TTS が誤読しやすい語は、**名前を教える所以外では言い換えて回数を減らす**。「数」の単独使用・同音異読の語（止める・後・方・節）は避ける（`tts-readings.md` C9）
- 製品名・UI の語は英字のまま書いてよい（画面も英字）。誤読したら講座の `tts-readings.tsv` で直す
- 画面に出す語は、**その行の語りで読む語だけ**。読んでいる間に画面が空にならない（タイトルだけの時間を作らない）
- F1 の語り: 「第N章、〇〇です。いまは、〇〇の△つ目、□□を学びます。」（まとまりの名前は `position_map` と同じ）
- 舞台裏の語・出どころの断りを語りに入れない（`quality-standards.md` 11）

### 台本のレビューの回し方（親）
1. **初学者役レビュー**（`templates/script-review_prompt.md`）。2ユニットずつに分けて並行で回し、1本ごとにファイルへ書かせる（1人に1レクチャー全部を渡すと止まって何も残らなかった）
2. **事実の照合**を並行で（`templates/fact-check_prompt.md`）。台本の設計メモに、事実の文ごとの根拠（事実の正本の節番号）を書いておく。初学者役も slide-reviewer も一次資料と突き合わせないため
3. 反映 → **作り直した箇所だけ再レビュー**
4. **日本語構成チェック**（`japanese-check.md`。リンターで終わらせず、1文ずつ読む → 差分の点検）。最後の手直しのあとにも1回通す
5. 音声へ

## コマンド（**`--help` をパイプラインのスクリプトに渡さない**。`audio.mjs` は `--help` で本処理が走る）

道具はプラグインの `scripts/`。下の `$P` を付けて呼ぶ。作業ディレクトリは講座の直下（`course.yaml` のある所）。

```bash
export PYTHONIOENCODING=utf-8
P="${CLAUDE_PLUGIN_ROOT}/scripts"
S=<course.yaml の faceless_scripts>          # 既定 ~/.claude/skills/faceless-explainer/scripts
U=<slug>

python "$P/make_unit.py" $U "<タイトル>" <doc-id>     # 新規ユニットのみ。既存は上書きしない
python "$P/tts.py" videos/$U                         # 音声。--only N で1行だけ作り直す。作った直後に <audio_backup_dir>/<日付>/$U/after-tts/ へ自動で退避（--no-backup で止める）
python "$P/check_reading.py" videos/$U [--frame N]   # STT で書き起こして台本と突き合わせる。一致率・付加脱落の兆候（漢字・かなだけを比べる）
python "$P/hira_check.py" videos/$U/assets/voice/*.wav   # 音をひらがなで書き起こす。英字・同音異読の語を含む行は必ず
python "$P/pad_audio.py" videos/$U                   # 行頭0.6秒・行末1.2秒の無音（冪等。元の wav を pad-before/ へ自分で退避）
python "$P/check_clicks.py" videos/$U --wav-only     # クリックノイズ（wav の先頭）
python "$P/make_beats.py" videos/$U                  # 語末の実測表 _beats.md
python "$P/new_storyboard.py" $U <id1> <id2> ...     # STORYBOARD の器（フレーム順の id）。無音フレームは duration を 6s に手で直す
(cd videos/$U && node "$S/audio.mjs" sync-durations --audio-meta ./audio_meta.json --storyboard ./STORYBOARD.md)
                                                     # ★ new_storyboard.py のあとに必ずもう一度回す（回さないと各 duration が既定の 5s に戻る）
python "$P/dump_beats.py" $U                         # videos/$U/.hyperframes/beats.txt に STT の語と語末の一覧
# slides.py を書く（手本をコピーして直す）
python "$P/unit_build.py" $U                         # 生成→組み立て→lint→check→継ぎ目→snapshot（各フレーム3枚）。Chrome を起動する
python "$P/check_idle.py" videos/$U                  # 読んでいるのに画面が増えない時間（NG は直す。警告は語りが長く読む間なら可）
python "$P/check_late_reveals.py" videos/$U          # 話し終わりの着地の候補
python "$P/check_nth.py" videos/$U                   # 同じ語が2回出る E() の回の一覧（★＝選んだ回）
python "$P/check_spacing.py" videos/$U               # 積んだ文字の行送り（候補。目で見て直す）
python "$P/check_coverage.py" videos/$U              # 占有率
python "$P/check_quiz_words.py" videos/$U            # 考えてみようの問いの語が1つの選択肢にだけ出ないか
python "$P/sheet.py" $U 1 4 7 ...                    # 着地の画像を並べる → videos/$U/.hyperframes/sheet.jpg を Read で見る
python "$P/slide_table.py" videos/$U --write <ユニット doc>   # §5 を書き出す
```

親が回すもの: `render_units.py <unit>`（**1本ずつ前景で**。回す前に空きメモリを見る。まとめて裏で流すとメモリ不足で止められる。止められたら `render_status.py` で数えてから報告）、`make_srt.py`（手元の確認用）、`make_lecture.py`。

### 音声の回し方
- **1本ずつ前景で**作る（複数をバックグラウンドで続けて回すと、メモリ不足で止められた）。`--only` なしで再実行しない（既存の音声が全部作り直され、語末が全部ずれる）
- 退避は `tts.py` が自動で行う。手で消さない。合成は再現できない
- 台本の順序を変えるときは、wav を後ろからリネーム → `audio_meta.json` の `frame`/`path` を直す → `--only`

### 音声の作り直し（誤読）のルール
- どこで止めるかは `tts-readings.md`「読みの確認を過剰にしない」。録り直すのは、狭い窓で聞き直しても疑う読みが**過半数**のときと、文の脱落・語の付け足しのときだけ
- STT の結果で**誤読の疑い**（語が別の意味になる）なら `--only N` で作り直す。**読めた時点で止める**（読めた版を次の周回で上書きしない）
- 同音の綴りの揺れ（正解→政界、回帰→会期）は誤読ではない。耳で確かめる語として報告する
- **`check_reading.py` は英字の誤読を一致率に出さない。** Cloud STT は英字の多い行の後半を丸ごと落とすことがある（音声は正しい）。脱落の兆候が出たら、作り直す前に `hira_check.py` で音を確かめる
- **`redo_until.py <unit> <frame> --need 語,語 --ban 誤読の綴り`** で自動化できる（読めた時点で止まる）。**`--need` に同音語を入れない**（STT が同音で返すので永遠に満たされず、空回りする）。`--need` は「語が別の意味に化けていないこと」の確認に使う。STT が5分を超えたら止めて `hira_check.py` で確かめる
- 辞書（`tts-readings.tsv`）でも直らない語は、台本の語を替える（「止める」→「防ぐ」）。決めた読みは報告に書く（辞書は親が足す）
- 作り直したら **pad_audio → check_clicks → make_beats → sync-durations → dump_beats** をやり直し、`slides.py` の `E()` と reveal を合わせる。音声を作り直す前に、退避があることを確かめる
- 録り直しで語末が動く。音声が確定してから slides の `E()` を書く（段階 C の順序）

## slides.py の書き方
- `render_pages(UNIT, D, PAGES, out)`。`PAGES = [(ページのタイトル, 解説文 or None, [(フレーム番号, id, 描く関数), ...]), ...]`。同じページの後のフレームは前の図が残る。実践の本体は `compact=True`（`slide-format.md` §9）
- 語末は `E(frame, "語")`（STT の綴りの連結）。**見つからないと KeyError で語の一覧が出る**ので、その綴りに直す（`dump_beats.py` の出力も見る）。同じ語が複数回ある時は `E(f, "語", n)`
- `s.reveal(名前, 語末, 注記)` は1フレーム最大6回。**フェード開始は 0.5 秒以降**。矢印は `s.arrow`。注記に `/*` を書かない（`check_crossfade.py` がブロックコメントと数える）
- `s.text(..., fit=幅)` が枠を超えると例外 → 短くするか文字を小さく。1.35cqw 未満の文字は使わない
- 意図した重ね（青を薄い行の上に重ねる等）は `overlap=True`。`check` の `content_overlap` が出たらここ
- 画面に出すのは図と短いラベル。**説明の文を箱にしない**。箱は図（対象・器）だけ。**中身の無い箱・図形を先に出さない**
- **形の意味を1つに保つ**。**同じ文字の札を左右に置いて ≠ で結ばない**。幾何・数で主張する絵（距離・最近点・棒の長さ）は**座標から計算して描き、`assert` を置く**
- 数値の例は画面に「例」と添える。問いのカードは、しくみのページと同じ数・同じ絵を使わない
- 「試験」の札: 要点の行（`lesson_rows(..., check=True, y0, y1, gap)`）に、語りに合わせて札を重ねる。行の中心 y は `lesson_rows` と同じ計算で出す（手本のユニットの関数を写す）
- 現在地: `position_map(s, GROUPS, gi, UNITS, ui, E(1, "…"), E(1, "…"))`。GROUPS・UNITS は `slide-format.md` §2d
- フォント・色: `frame.md` が正本（UD 書体・1色・白地）。色や px を手書きしない
- 1枚のリビールの数は、枠の付け替えや切り出しを分ける前に数える（上限6で止まる）

## 表示は話し始めに
画面の要素・行の強調は、**その要素を語り始める頃**に出す。`E(frame, "語")` は語の語末なので、**長い説明の行には文末の語でなく発話の最初の語**を渡す（例: `E(2, "データを")`）。要素が発話の終わりの語そのもの（結果の数・答え）なら語末でよい。
`check_late_reveals.py` で遅い着地（頭から2.5秒以上）の候補を、`check_nth.py` で同じ語の別の回（早すぎる着地）の候補を出し、1件ずつ判断する。
どちらも変数で渡した語末や、語の間がちょうど境目の回は拾わないことがあるので、**全 `E()` の出現位置を表にして突き合わせる**。

## 見やすさ
`slide-format.md` §2e。積んだ文章・式は行送り 1.4 倍以上／まとまりごとにカード（余白 8・24・64）／大きさは1枚に3段まで・太さ2種／意味の違う色は3色まで／**同じ型が3つ以上続くときは、終わったものを1行に畳む**。

## 目視（画像として読む）
`sheet.py` のコンタクトシートを必ず Read で見る（開始直後・途中・着地。抜き取りにしない）。見る観点: 文字のはみ出し・重なり、空の箱、語りで読まれていない語、画面の偏り（上半分だけ等）、語の揺れ（箱・カテゴリ・ラベル）。
スナップショットは各フレーム3時点だけなので、途中で枠が2つ残るかなどは、リビール直後を `npx hyperframes@<版> snapshot --at` で撮って見る（そのあと `unit_build.py` を回し直す）。直してから報告。

## 報告（短く）
段階 A: 設計メモ（使いどころの場面・しくみの具体例・考えてみようの問いと答え・選択肢の表・地図の行・事実の文ごとの根拠）＋ 台本の場所 ＋ 迷った点。
段階 C/D: 完成したか／尺／フレーム数・ページ数／各検査の結果／直したもの／直さなかったもの（理由）／**耳で確かめる語**／`slide_kit` に欲しい機能／新しく分かったこと（0〜3件。0件でも「なし」）。
