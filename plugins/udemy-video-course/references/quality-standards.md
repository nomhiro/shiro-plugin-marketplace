# 座学スライドと台本の品質の基準

座学レクチャーのスライドと台本を作るとき、作り直すとき、レビューするときに見る。
どれも、講座を1本ずつ作り直してレビューで差し戻された実例から決めた。
講座の用語の言い換え表や一次資料の事実は、講座リポジトリ側の規約に置く（このファイルは型だけを持つ）。

## スライド

1. **1枚に1つの現象。変わる前と後を並べる。** 「上書きすると変わる」と言うなら、変わる前の絵も画面に置く。
   比べる相手が画面に無いと、初学者には何が変わったのか分からない（初学者役のレビューで繰り返し出た指摘）。
2. **図の種類は内容で選ぶ。** 四角と線だけの図に寄せない。

   | 内容 | 向く図 |
   |---|---|
   | 表に値を当てて行が決まる・行が無効になる | 表の行を順に強調する図 |
   | どこに何があるか（入れ子）と、通り道・通らない道 | 配置図（入れ子の枠＋経路） |
   | やり取りの順序、向きの違い | シーケンス図 |
   | 判断や作業の順序の鎖・分岐 | フロー図 |
   | 比率・大小 | 棒グラフ |
   | 2つの並びの対応 | 対応表（左右の線） |
   | 範囲のどこからどこまでが何か | 範囲の帯（目盛り付き） |
   | 図にならない列挙（条件・注意点） | 箇条書き・表 |

3. **見た目だけの図を作らない。** 見出し付きの箱に文章を入れただけのカードは「図解っぽい箇条書き」で、
   制作者から「これなら箇条書きでいい」と差し戻された。関係（関連付け・設定・禁止）を見せたいなら、
   その関係を線で描き、禁止は線に ✕ を付ける。**1枚ごとに「この絵は何の関係を見せているか」を一言で言えるか**確かめる。
   言えないなら箇条書きにする。
4. **話の順に出す。** 図の要素は話に出た瞬間に現れるようにする。最初から全部出ていると、まだ話していない箱が見えて
   話と絵がずれる。台本では図の位置を指して話す（「図の1番」「破線にバツが付いている経路」）。
5. **最初の要素が出るまで、見出ししか映らない時間を作らない。** 段階表示のスライドで、最初の要素のきっかけが
   語りの遅い位置にあると、見出しだけの画面が 10 秒以上続く（実測：16 秒）。最初のきっかけは最初の段落の頭に置く。
   完成動画を `empty_frames.py` にかけて確かめる。
6. **ラベルは全部1行にそろえる。** 1つだけ2行になると、その箱だけ矢印の接続点がずれて見える。
   語の途中で折り返していないか（とくに否定の「い」だけが次行にぶら下がる形は、1行目だけ読むと肯定に見える）。

## 台本

7. **講師の一人称で話す。** 「受講者」→「皆さん」、「講師」→「わたし」。音声を作る前に台本を
   `受講者|受講生|講師` で grep して0件を確かめる（冒頭のお知らせなど、講座の外から話す回だけ例外）。
8. **用語は初めて出たところで一言で定義する。** 後のセクションで詳しく扱うものは、そのセクション名を添える。
9. **固有名を言い換えない。** SKU 名・製品名・プロトコル名・機能名を「やさしい呼び名」にしない。
   受講者は試験や実務でその固有名に出会う。言い換えた名前しか聞いていなければ、本物の名前を読めない。
   - 実測：3本で SKU を「等級」、機能名を「高速経路」のように言い換え、同じレクチャーの中で
     「SKU」と「等級」が混在した。どの機械検査もこの破れは捕まえず、PNG を全数見て気づいた。
   - 言い換えたくなる動機は、強調のきっかけ（cue）の照合キーが短くなることにある。それは cue の問題で、
     cue は台本から**別の句を選べば**済む。スライドと台本には実名を書く。
   - 実名に戻すと尺が伸びる。尺は冗長な説明を削って合わせ、固有名を削って合わせない。
10. **公式の日本語名で書く。** 製品の UI やドキュメントに日本語の正式名があるものは、それに合わせる
    （講座の用語表を正本にする）。台本を直したら、そのスライドの音声は manifest が作り直す。
11. **制作の舞台裏を指さない。** 「追跡している資料」「最終確認日」「スナップショット」「想定コストの欄」のように、
    受講者に見えない制作上の仕組みを台本で指さない。出典は公式ドキュメントの名前で言う。
12. **まだ公開が決まっていない回に言及しない。** 座学から「あとで実践でやります」と約束しない
    （実践の動画を出せるかが決まる前に約束すると、出せなかったときに嘘になる）。
13. **体言止めにしない・管理番号を読まない。** 全文を述語で締める。レクチャーの管理番号や試験項目のコードは
    読み上げ本文に出さず、タイトルや項目名で言う（`qa_check.py` が拾う）。
14. **TTS の事故を誘う文型を避ける。** 続きを予告して終わる文、英字ラベルや小数の羅列、2桁の手順番号は、
    合成が別の文を作ったり途中で切れたりしやすい。`tts-readings.md` を見る。

## 出し方と見やすさ（図解を中心にした座学で、制作者に差し戻された形から）

HTML などで1枚ずつ絵を描き、語りに合わせて要素を出す座学（241本）で、制作者の指摘を受けて決めた。
pptx のスライドにもそのまま当てはまる。

15. **表示と強調は「話し始め」に出す。** 要素は、その要素について話し始めた時点で出す。語の**語末**の時刻を
    きっかけにする仕組みでは、長い行に文末の語を渡すと、強調が読み始めの数秒後になる（全本で約200件あった）。
    行の最初の語をきっかけにする。同じ語が行に2回出るときは、出現回の取り違えを疑う。
16. **中身の無い箱・図形を先に出さない。** 箱は中身の語と一緒に、その語を読んだときに出す。
    「器を先に見せる」と、何の箱か分からない図形が先に映る。着地の絵だけでなく、**各枚の開始直後と途中**も見る。
    最終的に全部の箱に、語りで読まれた語が入っていること。
17. **箱は図だけに使う。** 名前・説明・要点を箱（札）にして図の横や下に置くと、図と同格に見えて読みにくい。
    説明は**タイトル直下の解説文**（タイトルより小さく、太字でなく、最初から表示する一文）にする。
    解説文がタイトルや図の言い直しになっていないか確かめる。
18. **教材ページを置く。** 1行ごとに絵が切り替わるだけだと「次々にページが映る」印象になる。
    詳細の前に「地図」（扱う項目の一覧と短い解説。読み上げに合わせて行を強調する）、
    締めの前に「要点」を置き、図解はその間に差し込む。
19. **語り1行＝1枚にしない。** 切り替えが多すぎると指摘された。関連する数行を1ページにまとめ、
    前の図を残したまま足していく（10行 → 5〜6ページ）。
20. **見やすさの数値**（デジタル庁デザインシステムから取り込んだもの）。内容が正しくても「見にくい」と差し戻された。
    - 積んだ行の行送りは文字の高さの 1.4 倍以上
    - まとまりの外の余白 ＞ まとまりの中の余白。区切りは線ではなく余白の差で作る
    - 文字の大きさは1枚に3段まで。太さは2種類。意味の違う色は3色まで。色だけで区別せず、語でも区別する
    - 同じ型が続くとき（指標を3つ順に説明するなど）は、終わったものを1行に畳む
21. **細字と太字を同じ座標に重ねない。** 字送りが違うので、行が長いほど後ろの文字が二重にぶれて見える。
    「薄い行」と「強調した行」は同じ太さで描き、濃さだけを変える。
22. **幾何で主張する絵は、座標から計算して描く。** 「いちばん近い点」に丸を付けたのに、別の点のほうが近かった
    （レビュー役が距離を計算して見つけた）。目で置かない。
23. **同梱の書体に無い字を使わない。** 日本語のサブセット書体には `→` `★` `ε` `γ` などが無いことがある。
    矢印や星は図形で描き、ギリシャ文字は読み（イプシロン）を添える。書体の cmap を走査して確かめる。

## 台本（続き）

24. **音だけで通じるか。** 1音の語（「葉」「は」）や「も」は、耳では紛れる（「葉にたどり着けば」→「枝の先にたどり着けば」）。
    音声認識が取り違えた箇所は、人の耳でも曖昧なことが多い。
25. **台本は膨らむ。** レビューを反映するたびに 100〜200 字増える。音声を作る前に字数の上限を決め、
    反映のたびに詰める。音声のあとに削ると録り直しになる。
26. **概念の数に合わせて長さを決める。** 型（使いどころ・しくみ・考えてみよう など）の長さに合わせて水増ししない。
    概念が2つ以下なら、使いどころと分かれ目を1枚にまとめる。
27. **「考えてみよう」の問いは、しくみの言い換えで解けないものにする。** 直前に見せた数や言い回しをなぞるだけで
    答えが出る問い、消去法・鏡写し・選択肢の形の違いで解ける問いは、考える時間にならない。
28. **受講者目線は、レクチャーを通して見る。** 受講者が1本として見る単位（冒頭 → 本編 → 末尾）で、
    冒頭に「なぜ学ぶか・どこに位置するか」、末尾に全項目の一言の振り返りと小テストと次の回があるかを確かめる。

## レビューと検査の順序

- **音声を作る前に**、初学者役のレビュー（用語の説明の抜け・話と絵のずれ・見た目だけの図・固有名の言い換え）を
  1回通し、指摘を直してから TTS にかける。音声を作った後に直すと、TTS の費用と照合をもう一度払う。
- **スライドの PNG は全枚数を見る。** 抜き取りでは当たらない（実測：数枚見て「問題なし」としたレクチャーに、
  全37枚を見た検査で3種の欠陥が見つかった。1本30〜45枚のうち欠陥は2〜3枚）。
- 事実の主張は一次資料（公式ドキュメント）で裏を取る。一次資料どうしが食い違うときは断定しない言い方にし、
  制作者の判断が要る点として挙げる。
