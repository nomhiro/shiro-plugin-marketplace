# 読み上げ表記一覧（TTS の誤読対策）

ナレーション台本を TTS（Gemini-TTS）で音声にすると、英字の略語や記号が**意図と違う読み**になることがある。
TTS 側に**読み替え辞書は無い**（`lecture_movie.py` / `practice_movie.py` を確認）ので、**台本の表記そのものを直す**。
この一覧は、その「台本での書き方」の正本。**台本を書く前に一度見る。誤読を見つけたら追記する。**

## 使い方の原則

- 適用先は台本（`_transcript.md` / `_transcript_rec.md`）の**本文だけ**。
  **見出し行（`## スライドN:` / `## 録画N […]:`）は変えない**（ページ対応のマーカーであり、読み上げ対象でもない）。
- **スライド・画面に出る文字は元の表記のまま**（`az login` と書いてあるスライドを、耳では「エーゼットログイン」と言う）。
- 日本語が続くときは空白を落とし、英単語が続くときは空白を残す（下の例を参照）。
- 直したら、**本文が変わった区間の音声だけ**を再合成する（手順は末尾）。

## A. 確定（誤読を確認済み）

| 元の表記 | 誤読 | 台本での書き方 | 例 | 確認 |
|---|---|---|---|---|
| `az`（Azure CLI）／`Az`（Az PowerShell） | アズ | **エーゼット** | `az login` → **エーゼットログイン** ／ `az コマンド` → **エーゼットコマンド** ／ `az resource update` → **エーゼット resource update** ／ `Az PowerShell` → **エーゼット PowerShell** | 2026-09-21 制作者の指摘 |
| `手順11`（2桁の手順番号） | 「11」が抜ける／「いちいち」 | **十一番目の手順で** のように言い換える | 「手順11で」→「続いて、十一番目の手順で」 | 2026-09-24 STT 照合で検出（2回連続） |

- 対象は**単独の `az` / `Az`**。`azure-identity`・`azcli`・`Set-AzCognitiveServicesAccount` のように識別子の一部になっているものは対象外（下の C を参照）。
- 全台本を洗い出すときの正規表現：`(?<![A-Za-z0-9_.\-])[Aa]z(?![A-Za-z0-9_])`

## B. 記号の読み下し（既存の台本で使っている慣習）

URL・スコープ文字列・`名前=値` のような**記号を含むものを読み上げる**ときは、記号を日本語で読み下して書く。

| 記号 | 台本での書き方 | 実例（既存の台本） |
|---|---|---|
| `.` | ドット | `ai ドット azure ドット com スラッシュ ドット default`（Foundry のスコープ）／`management ドット…` |
| `/` | スラッシュ | `api スラッシュ projects スラッシュ プロジェクト名` ／ `openai スラッシュ v1 スラッシュ` |
| `=` | イコール | `api_key イコール文字列` |
| `:` | コロン | `エージェント名コロンバージョン`／`my-agent コロン 1` |

- URL は**全部を読み上げず**、「末尾が〜で終わる」のように**要点だけ**言うほうが聞きやすい。

## C. 確認待ち（音声で誤読の有無を確かめてから確定する）

推測で「正しい読み」を決めない。**実際に合成して聞き、誤読なら A に移す。**

| 表記 | 状況 |
|---|---|
| `azcli` | ファイル名・拡張子。「azcli ファイル」と書いた台本がある。読みは未確認 |
| `azure`（URL の中） | 既存の台本で書き方が割れている：`…ドットアジュールドットコム`（カナ）と `ai ドット azure ドット com`（英字）。どちらで正しく読まれるか未確認 |

## C2. 途切れ・ループを起こしやすい文（誤読ではなく合成の失敗）

- **英字のラベルや小数が続けて並ぶ文**（例：`positive 0.98, negative 0.01, neutral 0.01 …`）は、
  合成が途中で打ち切られたり、長い無音が挟まったりしやすい。実測では同じ文で4回中3回失敗した。
  値は画面に任せ、ナレーションでは「ポジティブがほぼ1で、残りはほぼ0です」のように言い換える。
- `qa_check.py` の「途切れ疑い」「長い無音」が同じ区間で繰り返し出るときは、再合成を重ねず、
  文を言い換える。

## C3. 台本に無い文を読み出しやすい区間（合成の「作り話」）

実測（完成済み25本を STT で照合、2026-09-24）で、約30区間が台本と違う内容になっていた。
長さが近いものは qa_check では見逃すので、`verify_tts.py` で照合する。起きやすかったのは次の形。

- **続きを予告して終わる文**（「〜注意しておきたいことがあります。」で区間が終わる）
  → 合成が「続き」を勝手に話し、無関係な説明が付く。**区間の中で言い切る**（「〜を次のスライドで確認します。」）。
- **「末尾が〜が返りました」で始まる短い区間** → 冒頭に前置きが付く・別の文になる（4本で同じ形）。
  **主語から始める**（「プロジェクトの URL が返りました。最後が〜で終わっています。」）。
- **スタイル指示の読み上げ**：「親しみやすいオンライン講座。ナレーターは受講生一人一人に語りかけるように…」
  が冒頭に付く。区間の内容と関係なく起きるので、再合成で直す（1〜2回で直ることが多い）。
- **冒頭・末尾の1文の脱落、語の入れ替え**（「青いボックス」→「オレンジのボックス」）。

- **台本に無い文を足す・全文を2回読む**（新しい世代のモデルで実測）。区間の長さが倍近くになるか、
  適合率が 0.47〜0.60 まで下がる（再現率は高いまま）ので、`verify_tts.py` の「台本に無い文」で拾える。
  長さが近い付け足しは `qa_check.py` の比では見逃す。

直し方：NG の区間の wav だけを別の場所へ**移動**（削除ではなく退避。比較に使う）→ `--audio-only`
（無い wav だけ作られる）→ その区間を照合、を2回まで。続けて外れたら文を言い換える。

## C4. 区切りの長さと速さ

- 長い台本は文の区切りで約 250 字ずつに分けて合成し、つないでいる（`--max-chunk-chars 250`）。
  約2分を超える音声を一度に作ると読み上げが速くなるため。
- 「区切りの中で後ろほど速くなる」と指摘されたとき、250字・120字・1文ずつ・「同じ速さで」の指示付きを
  作って聞き比べた。1文ずつ作った版を基準にすると、後ろほど速くなる傾向は無かった
  （区切って作ると全体が約1割速い、120字は区切りごとに速さが跳ねる、指示付きは遅く落ち着く）。
  聞き比べで制作者は 250 字を選んだ。
- **速さを測るときは、同じ文を1文ずつ合成した版を基準にした比で比べる。** 字数/秒を前後で比べるだけの集計は
  文の中身の差を拾うので、結論に使わない（最初の「後半が1割速い」はこの誤りだった）。

## C5. モデルを変えるとき

- **1本の中でモデル・声を混ぜない。** スライドごとに声の質が変わる。`lecture_movie.py` / `practice_movie.py` は
  音声フォルダの manifest にモデルと声を記録し、既存の音声と違うモデルで作ろうとすると**何も合成せずに止まる**。
  作り直す回は音声フォルダを `<名前>.bak_<日付>` へ退避（移動）してから全区間を作る。
- モデルを変えた最初の数本は、`verify_tts.py` で**全区間**を照合する。事故の出方がモデルで変わる。
- モデルによって返す音声の形式が違う（ヘッダ付きの WAV か、生の PCM か）。そのままつなぐと境目に雑音が入るので、
  新しいモデルを足すときは1区間を作って波形の頭を確かめる。

## D. 追加・修正の手順

1. 音声を聞いて誤読を見つける（制作者の指摘でもよい）。
2. **全台本を洗い出す**（同じ表記が他のレクチャーにもある。`grep -r` か上の正規表現で、`_audit_backup` を除く）。
3. 台本の**本文だけ**を直す（見出し行は触らない）。ドライランで置換後の文脈を目視してから適用する。
4. **本文が変わった区間だけ**音声を再合成する：
   - **実践**：`practice_movie.py build <ID>`（本文が変わった区間だけ再合成される。変わらない区間は `= skip … 本文不変`）
   - **座学**：`lecture_movie.py <ID> --audio-only`（manifest が本文の変わった区間だけを作り直す。wav を手で消さなくてよい）→ `lecture_movie.py <ID> --video-only --force`（音声は再利用）。
     `speech_NN` の番号は、**台本に本文のある `## スライドN:` をスライド番号の昇順に 1,2,3… と振ったもの**（スライド番号そのものではない）。
     途中にスライドを足すと以降の番号が繰り下がり、manifest が本文の違いとして作り直す。
     manifest の無い古い音声フォルダでは、最初の1回だけ止まる（モデルが分からないため）。同じモデル・声で作り、**その後に台本を直していない**と確かなときだけ `--adopt-existing`（今の台本で作ったものとして記録されるので、直した覚えがあるなら退避して作り直す）。
   - **モードB の実践**（フレームから組んだもの）：台本を直したら `build_rec.py --audio-dir` → `analyze --force` → `build --video-only` の順で組み直す（尺は実音声で決まる）。
5. **この一覧に追記する**（表記・誤読・書き方・確認日）。
