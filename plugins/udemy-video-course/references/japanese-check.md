# 日本語の構成チェック（音声の前・制作者に見せる前の門）

台本・小テスト・README（教材リポジトリ）・制作者に見せる文書は、**音声を作る前、制作者に見せる前に**、
`yomiyasu` スキルで日本語の構成チェックを通す（2026-10-18 制作者の指示「必ず日本語構成チェックをするようにして」）。
AI が書いた日本語の不自然な比喩・曖昧な主述・偏った構文・文末のコロンなどを直す。

## 手順

1. リンター: `PYTHONIOENCODING=utf-8 python <yomiyasu>/scripts/yomiyasu_lint.py <file>`（Git Bash では文字化けするので環境変数を付ける）
2. **リンターで終わらせず、1文ずつ読む。** 主語と述語のかみ合わせ、つなぎ言葉の接続先、予告だけの文を見る
3. 直す
4. 差分の点検: `yomiyasu_diff.py <元> <直した後> --stance=説明`（台本・README は説明。手順書は決まり）
5. 音声の後に直すと録り直しになる。**音声の前に通す**

## 台本で残すもの（直さない）

- TTS の間を作る読点（音声の区切りのために置いた読点は、読点の数の目安を超えても残す）
- 「考えてみよう」の選択肢の常体（「〜を受け入れる」）。語りの中の選択肢で、です・ますにそろえない
- 誤解を正す否定（「AではなくB」）。主張の比重を担っているので、肯定文にしない
- 製品名・機能名の英字（言い換えない。`quality-standards.md` 9）

## 落とし穴

- **英単語の前後の空白を一括で消すと、番号付きリストの `1. 手順` の空白まで消えて、リストが崩れた**（README）。
  行頭の番号・見出しの番号の後ろの空白は残す。一括の置き換えはせず、行ごとに直す
- 参考の一覧（表や箇条書きが中心の文書）は、箇条書きの比率と英字の識別子の前後の空白を直さなくてよい。直さなかったことを文書の頭に1行書く
- 文末のコロン（「次のとおり：」）は、「次の表のとおり。」「〜ものは、〜です」に直す
