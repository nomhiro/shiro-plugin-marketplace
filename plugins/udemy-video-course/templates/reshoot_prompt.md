# 実践レクチャーの撮影・撮り直しの依頼文（テンプレート）

`<...>` を埋めて、撮影担当のサブエージェントに渡す。ブラウザは1つなので、撮影は同時に1本だけ。
講座の教訓ファイル（`templates/course-lessons.md` から作ったもの）を「講座の教訓」の節にそのまま差し込む。
依頼文の本体は講座ごとに書き直さない。教訓が増えたら教訓ファイルのほうに足す。

<講座名> の実践レクチャー <ID> を<撮影｜撮り直し>してください。<報告の言語>で報告。
制作者は<撮り直し・リソースの作成と削除>を許可済み（<日付と範囲>）です。管理画面には、
ブラウザ操作の拡張のタブグループ内のタブでサインイン済みです。

**読むもの**：講座の CLAUDE.md／用語規約／プラグインの record-practice-screen と make-practice-movie の SKILL.md／
<点検の指摘のファイル（あれば。これを全部解消するのが目的）>／同じトピックの座学の確定版の台本
（主張を食い違わせないため）／講座の教訓ファイル。

**手本**：<直前に撮った1本の作業ディレクトリと、使ったスクリプト>。同じ道具立てで作る。

**作り方**
1. 解説ドキュメントと撮影計画を、管理画面（コンソール）主体に直す。CLI はコンソールに画面が無いものだけ。
   事実は一次資料で確かめて直す。課金の仕組みと金額は断定しない（「残っている間は課金が発生しうる」
   「料金は料金ページで確かめる」まで）。
2. 撮る前に、そこで使う SKU や設定の組み合わせが**本当に選べるか**を画面で確かめ、台本を画面に合わせる。
3. コンソールで 作成 → 確認（観測）→ 削除 まで撮る。**画面に着くまでの手前**（検索 → 候補 → 一覧 → ［＋ 作成］）
   を1区間ずつ撮る。**観測でも URL で直接飛ばない**（検索か左のメニューで移動し、その1コマを撮る）。
   リソースグループ名には講座の識別子（<course>）を入れ、一覧は撮る前に絞り込み欄へ識別子を入れる。
   ダッシュボードなど、累計コストや他プロジェクトが出る画面は撮らない。作る前に同じ名前のものが無いか確かめる。
4. 最後に必ずリソースグループを削除し、**一覧が 0 件になった画面を撮る**。RG の外に残るもの（診断設定、
   RG の外に付けたロール割り当て、別の RG に作られる付随リソース）を先に外す。途中で失敗しても、
   作ったものは必ず消してから報告する。消せなかったら報告の先頭に「重大：残存リソース」と書く。
5. 撮った枚は `ingest_shot.py add --expect <WxH>` で取り込む（寸法の違う枚は記録されない）。
6. 映り込みは黒ベタのみ（ぼかし禁止）。`ocr_mask.py --rules <講座の規則ファイル>` で塗り、
   `leak_check_ocr.py` で塗り残し 0 件を確かめ、コンタクトシートで全数を目視する。
7. 強調（押す場所・打ち込む欄・見る場所）を全区間に入れ、`box_fit.py` と `cue_stills.py --sheets` で全数確かめる。
   台本は講師の一人称、講座の用語規約の名前、固有名は言い換えない。
8. TTS：既存の音声フォルダは消さずに `<名前>.bak_<日付>` へ退避してから全区間を作る（1本の中でモデルを混ぜない）。
   全区間を `verify_tts.py` で照合し、NG はその区間だけ作り直す（照合は長いのでバックグラウンドで流す）。
9. 動画を組む。既存の mp4 は退避してから上書き。完成動画をシートで全数目視（映り込み・強調の位置・音と画面のずれ・沈黙）。
10. 配布資料（ハンズオンの README など）に指摘があれば直す。

**デスクトップに触らない**
- 操作してよいのは、ブラウザ操作の拡張のタブグループ内の対象のタブと、自分のシェルだけ。ほかの窓・ほかのタブを
  前面にしない、キー入力を送らない、閉じない。OS の GUI 自動操作（証明書の管理画面・メモ帳・エクスプローラーなど）はしない。
- 画面の取得は拡張のスクリーンショットだけ。デスクトップ全体や窓のキャプチャ、窓の題名の列挙は、読み取りだけでも禁止。
- クリップボードを上書きしない。ファイルをダウンロードしない（必要なら「ダウンロードできる」画面までを撮る）。
- 端末の画面は、実際に打ったコマンドと実際の出力をそのまま映す。
- 撮影用の窓が無いときは、拡張の機能でタブグループに専用の窓を作る。

**撮影が止まったら**
- ブラウザの窓が隠れて（hidden）スクリーンショットが撮れなくなったら、直そうとしない。**作ったリソースを CLI で
  消し、消えたことを確かめてから報告する。** 再開は制作者の指示を待つ。
- サインインが切れたら止まって報告する（パスワードや多要素認証は入力しない）。

照合の結果、残った懸念、**新しく分かったこと（0〜3件。教訓ファイルの書式で。無ければ「なし」）**。
