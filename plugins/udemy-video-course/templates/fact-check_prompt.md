# 事実の照合の依頼文（テンプレート）

`<...>` を埋めて、照合の担当（サブエージェント）に渡す。**音声を作る前に**1回通す。
初学者役のレビュー（`script-review_prompt.md`）も slide-reviewer も一次資料と突き合わせないので、
**自律で進めるときの門として、事実の照合は別に回す**（ある講座の1回目で、全112文のうち言いすぎ6・ずれ2）。

---

<講座名> の <レクチャー ID> の台本（<SCRIPT.md の一覧>）と小テスト（<quiz.md>）の事実を、一次資料と1文ずつ照合してください。
<報告の言語>で報告。**直さず、照合の表だけ**を書きます。

**正本**（この順に当たる）
1. <講座の事実の正本（research/ の digest・機能の状態の表）>
2. 正本に原文が無い、または要約しか無い文は、一次資料（<docs の URL の範囲>）を WebFetch で開いて逐語で確かめる。確かめた日を書く

**対象**
- 字下げ行（読み上げる行）と小テストの問い・選択肢・解説のうち、**事実を述べる文だけ**。場面の設定・つなぎ・問いかけ・「試験では〜押さえましょう」は除く
- 画面に出す文（スライドの見出し・札）も、事実を述べていれば対象

**判定**
- 一致／**言いすぎ**（原文より強い・広い）／**ずれ**（原文と違う）／**根拠なし**（正本にも一次資料にも無い）
- 「一致（注）」は一致に数え、気になる点を直し方の欄に書く

**見る点**
1. **数を言う文は、原文の箇条を数える**（「次の5つ」→ 原文は6つだった）
2. **要点・まとめで、本編の限定を落としていないか**（本編は「個人のプランでは」、まとめは限定なし、など）
3. 関係の断定（「AとBは同じものの現れ方」）・因果（「〜が原因で」）が原文にあるか。もっともらしい因果を足していないか
4. 頻度・重要度の断定（「よく問われる」「必ず出る」）に根拠があるか
5. 機能の状態（GA・プレビュー・終了）と、プラン・料金・上限の値が、機能の状態の表と今の資料に合っているか
6. 資料どうしで割れる値（ページによって違う）を、断定していないか。割れているなら、その値を扱わない案を出す
7. 小テストの正解が原文で正しく、誤答が原文で確かに誤りか（「どちらとも読める」誤答は高）
8. **レビュー役の直し案（前の回のレビューの案）を採った文も、裏を取る**

**出力**
- `<書き出し先>` に、ファイルごとの表を書く: `| 行 | 文（短く） | 正本の § と原文（英語は原文のまま） | 判定 | 直し方の案 |`
- 頭に件数（一致・言いすぎ・ずれ・根拠なし・全文数）と、照合日・正本・逐語で確かめた URL を書く
- 最後に短く返す: 言いすぎ・ずれ・根拠なしの一覧（ファイルと行）／正本に足すべき事実（あれば）

**しないこと**
- 台本・小テスト・正本を直さない
- 出典の名前を台本に足す案を出さない（講座の方針が「出どころを言わない」の場合。<出どころを言うか>）
- スクリプトに `--help` を渡さない
